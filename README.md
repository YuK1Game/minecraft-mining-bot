# Minecraft Realms Bot

Minecraft 統合版の Realms に、別のプレイヤーとして参加する開発中の自動化 Bot です。接続を保ったまま行動コードを更新できます。

現在の目標は **指定範囲を上から1層ずつ露天掘りし、回収した資材を収納すること**です。通常の採掘・回収・搬入と戦闘を組み合わせ、途中からの復旧にも対応します。2026年11月4〜5日に実Realmで5,000ブロック以上の採掘を確認していますが、ジョブ全体の完了は引き続き検証中です。ダイヤモンドの取得は現在の目標ではありません。

## 起動

Node.js 24 以降と、対象 Realm に参加できる Minecraft 統合版用 Microsoft アカウントが必要です。普段のプレイヤーと同時に遊ぶ場合は、Bot 用の別アカウントを Realm に招待します。

```powershell
Set-Location G:\Projects\MinecraftBot
npm install
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
npm start
```

初回はターミナルに表示される Microsoft 認証ページでコードを入力し、Bot 用アカウントを選びます。普段のアカウントが自動表示される場合は、シークレット／InPrivate ウィンドウで開き直します。`REALM_ID` が空欄なら一覧から接続先を選び、`q` で取り消せます。接続後は、後述の `/quarry plan` で計画を確認し、`/quarry start` で露天掘りを開始します。

| コマンド | 動作 |
| --- | --- |
| `npm run auto` | 旧サバイバルの自律実行。異常終了時の再接続監視付き |
| `node scripts/keep-alive.js --connect-only` | Realmに接続し、異常終了時は同じモードで再接続。露天掘りの状態は `/quarry status` で確認し、必要に応じて `/quarry resume` で再開 |
| `npm run auto:once` | 旧サバイバルの自律実行を1プロセスだけ起動。終了後の自動再接続なし |
| `npm start` | 接続してコード更新を監視。露天掘りは `/quarry`、旧サバイバルは `/auto` で開始 |
| `npm run realms` | 参加できる Realm の一覧を取得。ワールドへは入らない |
| `npm test` / `npm run check` | 自動テスト / 構文確認。ゲームの達成証明とは別 |

同じアカウントをゲーム画面と Bot で重ねて使う場合は、先にゲーム側を対象 Realm から退出させてください。

## 統合ダッシュボード

```powershell
npm run dashboard
```

同じPCで [http://127.0.0.1:3001](http://127.0.0.1:3001) を開きます。露天掘りの状況、Botの所持品・装備、シュルカーボックスの中身、ライブのBotログを同じページで確認できます。アイテムを選ぶと、数量・耐久度・エンチャント・カスタム名などの詳細を表示します。所持品のシュルカーボックス枠をクリックすると、ポップアップで中身を表示します。中のアイテムの数量・耐久度・エンチャントも、その場で確認できます。所持品や内容がサーバーから届いていない場合は「未確認」と表示し、空とは扱いません。

露天掘りの表示では、作業層・採掘数・回収数・搬入数に加え、採掘が終わったか、地上への復帰が確認できたかを個別に確認できます。「地上への脱出」欄には土の所持数、必要数、不足数、停止理由を表示します。脱出列の選定前は土の確保目安と見積不足を表示します。旧ログページ `/logs` は統合ページのログ欄へ移動します。ログの時刻はJSTで、文字列や種類で絞り込めます。

監視サーバーはBot本体と別に動き、Botの退出中は最後の確認値とその時刻を表示します。画面は表示専用で、Botの操作用APIや認証情報は公開しません。表示用の最終確認値は `.local/dashboard-last.json` に保持します。状態はページ閲覧中に約5秒間隔でBotから取得し、ログは追記を配信します。画面の変更後は監視サーバーを再起動してください。所持品の詳細表示は行動コードのホットリロードで反映できます。

## 停止と再接続

| ターミナル入力 | 動作 |
| --- | --- |
| `/status` | 接続、体力、持ち物、行動、自律実行、コード更新の状態を表示 |
| `/auto` | 現在の観測と保持した進捗から自律実行を開始 |
| `/stop` | 自律実行と行動を停止し、接続を維持。ワールド内の時間は進む |
| `/reload` | 保存した行動コードを手動で反映 |
| `/quit`、`Ctrl+C` | 接続とプロセスを終了。自動再接続もしない |

`npm run auto` と `node scripts/keep-alive.js --connect-only` は、どちらも `scripts/keep-alive.js` が子 Bot を監視します。前者は旧サバイバル自律を開始し、後者は接続だけで起動します。**非ゼロの終了コードで異常終了した場合だけ**、待ち時間を2秒から指数的に増やして同じモードで再接続します。初期設定は待ち時間最大60秒、10分間に再起動最大5回です。上限に達すると停止します。

正常終了、明示した `/quit` や API の `/disconnect`、停止シグナルによる終了では再接続しません。`/stop` はプロセスを終了しないため、再接続も発生しません。行動コードの保存も接続を切り替える理由にはなりません。

## 設定

既存の `.env` を編集します。

| 設定 | 初期値・用途 |
| --- | --- |
| `BOT_PROFILE` | `main`。認証を分けるローカル名。別アカウントなら `bot` などへ変更 |
| `REALM_ID` | 空欄なら一覧選択。指定すればその Realm に接続 |
| `MINECRAFT_VERSION` | 空欄。現在の行動実装は `1.26.60` 用 |
| `API_PORT` | `3000`。同じ PC 内の API 待受ポート |

認証キャッシュは `.auth/<BOT_PROFILE>/` に保存します。パスワードを設定ファイルへ書く必要はありません。`.auth/`、`.env`、`.local/` は Git の管理対象外です。

## 旧サバイバル自律実行の順序

以下は露天掘りとは別に残している旧 `diamond` 目標の動作です。現在の作業には後述の `/quarry` を使います。

1. 既知の土・草の斜面に小さな避難所を作るか、平地に土17個で壁と屋根のある小屋を建てる。実際の土の取得と消費を確認して入口を閉じ、外へ出る時は自分が施工した入口だけを開ける。
2. 原木約2個から板材・作業台・棒を用意し、まず木剣を作る。
3. 木剣を実際の持ち物で確認してから、木のツルハシ・石材を用意して石剣へ進む。既に材料があれば直接石剣を作る。
4. 石のツルハシ、かまど、石炭、鉄の原料と精錬を経て、鉄のツルハシを作る。摩耗した道具は交換を準備する。
5. 受信した地形にある鉱石へ、安全を確認しながら掘り進む。**サーバー由来の持ち物にダイヤモンド1個以上が入った時だけ最終完了**とする。

避難所の最初の目標は小さな閉鎖空間です。作業台・かまど用の3×2の部屋は将来の拡張として分け、未施工の領域を完成済みとは扱いません。木剣のプレビューや石材の達成だけでも最終完了にはなりません。

敵の接近、体力、食料、持ち物、地形を観測します。退避・自衛・狩り・食事の操作を実装していますが、生存を安定させる調整は継続中です。未知地形、未確認の持ち物、危険な施工、未実装機能、繰り返す失敗では待機または停止します。

## 接続を保ったコード更新と記録

接続を持つ `src/host.js` と、差し替える `src/runtime.js`・行動モジュールを分離しています。行動コードを保存するとホットリロードし、同じ接続の観測と持ち物を使って再開します。構文や初期化に失敗した変更は採用せず、旧コードを保持します。クラフト・設置などの途中では安全な切替点を待ちます。

安定ホスト、認証・通信の中核、依存ライブラリ、`.env` などの設定を変えた場合は必要に応じて再起動します。監視対象と適用世代は `/status` の `hotReload.watchFiles` / `generation` で確認できます。

避難所と土小屋の施工 memo はホットリロードを跨いで保持します。新しいホストで起動すると、`.local/mission-memory.json` に記録を保存し、接続先の Realm・プロファイル・次元が確定してから復元します。既に進行中の記録を上書きせず、途中で接続や処理世代が変わった読込結果も採用しません。終了時には保存待ちを行います。古いホストを接続したまま行動コードだけ更新した場合、ディスク連携は次回起動から有効です。

記録の保存・復元は結合テストまで確認しており、自然切断からの一連の自動復帰は実地検証中です。復元した記録だけで安全や完成を認定せず、現在の壁・屋根・入口を再確認します。未確認の設置や回収は成功記録へ昇格しません。

移動の予測位置と最後に受信したサーバー位置は分けて扱います。回収・クラフトは実際の持ち物の変化、採掘は受信した空気、設置はブロックと消費の両方を確認します。ドロップの消滅や予測上の到着だけでは取得成功としません。

## ローカル API

同じ PC の `http://127.0.0.1:3000` で利用します。POST は JSON と `Content-Type: application/json` が必要です。

```powershell
$base = 'http://127.0.0.1:3000'
Invoke-RestMethod "$base/status"

# 旧サバイバル目標での自律実行の開始（露天掘りは後述の quarry を使用）
$body = @{ objective = 'diamond'; diamondCount = 1 } | ConvertTo-Json
Invoke-RestMethod -Method Post -ContentType 'application/json' -Body $body "$base/agent/start"

# 行動停止。接続は維持する
Invoke-RestMethod -Method Post -ContentType 'application/json' -Body '{}' "$base/agent/stop"

# 読み取り用の拠点候補プレビュー
$body = @{ group = 'shelter'; method = 'preview'; args = @(@{ radius = 8 }) } | ConvertTo-Json -Depth 8
Invoke-RestMethod -Method Post -ContentType 'application/json' -Body $body "$base/action"
```

| API | 用途 |
| --- | --- |
| `GET /status`、`GET /blocks?radius=1` | 状態・受信した地形の確認。`known:false` を空気扱いしない |
| `POST /agent/start`、`/agent/stop`、`/agent/tick` | 自律実行の開始・停止・1回の判断 |
| `POST /reload`、`/disconnect` | コード更新 / 明示的な終了 |
| `POST /move/preview`、`/move/start`、`/move/stop` | 経路移動。目標の `y` は足元 |
| `POST /mining/preview`、`/mining/start`、`/mining/stop` | 整数座標のブロック採掘 |
| `POST /craft/preview`、`/craft/start`、`/craft/open`、`/craft/close` | 受信済みレシピによるクラフト |
| `POST /combat/attack`、`/combat/defend`、`/combat/stop`、`/respawn` | 自衛、停止、正規リスポーン |

追加機能は `POST /action` の `{ "group": "...", "method": "...", "args": [...] }` で呼び出します。`execute` などは実際にワールドや持ち物を変更します。

| group | 主な method・用途 |
| --- | --- |
| `shelter` | `preview` / `execute` / `leave` / `snapshot` / `stop`。斜面の避難所の施工と退出 |
| `hut` | `preview` / `execute` / `leave` / `snapshot` / `stop`。平地の土小屋の建築・閉鎖・退出 |
| `guardRoute` | `execute` / `returnRoute` / `escape` / `snapshot` / `stop`。装備・敵・被ダメージを監視する経路移動と退避 |
| `safety` | `start` / `stop` / `snapshot`。待機中の自衛・小屋閉鎖・退避不能時の非常停止。初期状態は無効 |
| `interactions` | `previewPlace` / `placeBlock` / `openFurnace`。作業台・かまど・土・床置きたいまつの正規設置と使用 |
| `food` | `preview` / `eat` / `snapshot` / `stop`。実際の食料を食べる |
| `foraging` | `preview` / `execute` / `snapshot` / `stop`。食料用動物の追跡・狩り・回収 |
| `combat` | `preview` / `attack` / `previewEngage` / `engage` / `stop`、`previewHunt` / `hunt`。剣による限定時間の自衛と食料用の狩り |
| `inventory` | `equip`。アイテムをサーバー確定の選択スロットへ移す |
| `furnace` | `putInput` / `putFuel` / `takeOutput` / `snapshot`。投入・燃料・精錬結果の受領 |
| `prospecting` | `start` / `snapshot` / `stop`。受信した地下地形から鉱石を探す |
| `excavation` | `preview` / `execute` / `snapshot` / `stop`。隣の1セルを同高・1段上・1段下へ掘って移動 |
| `tunneling` | `preview` / `execute` / `snapshot` / `stop`。確認済みの鉱石へ短い掘削工程を組む |

長い処理は状態を確認しながら扱います。入力を送ったこと、時間が経過したこと、プレビューが通ったことだけでは成果になりません。

`guardRoute` の座標は足元です。通常は実所持の剣を装備してから動き、最初の被ダメージや危険な敵を確認すると資源への移動を中断します。 出発時の体力下限は既定14で、剣を確認できる食料・道具の準備に限り `minimumOutwardHealth:10` を明示できます。初回被ダメージ時の中断は維持します。`visitedPrefix` は同じワールドで実際に通った順序の足元座標であり、計画だけの地点を渡してはいけません。`returnRoute` はその逆順へ戻り、小屋の入口付近が帰着点の時だけ、現在の小屋を確認して閉鎖します。

現在すでに敵が近い時に安全域へ離れる用途は `escape` です。全経路が確認済みで、敵から離れる場合だけ緊急移動します。明示した `escape` では、未武装でも `maxLegDistance:12` まで指定し、確認済みの経路を連続移動できます。通常の未武装移動は1区間2ブロック、未武装の明示指定の上限は64地点・指定地点間の距離48ブロックです（既定は8地点・12ブロック）。Nav内部の迂回を含む実際の歩行距離とは区別します。走行は実際の空腹値と足場が許す区間に限ります。到着しても `safe:true` や小屋への帰還に置き換えず、`escaped`・`riskRemains`・現在の敵と位置の確度を確認します。失敗理由は `GET /status` の `guardRoute.routeRejection` に残ります。元の移動中断は `routeInterruption`、帰着後の小屋閉鎖は `refugeClosure` として別々に記録します。実行APIは終了まで待つため、クライアント側のタイムアウトを実行時間より長くしてください。

未武装で最初の木材を採る場合だけ、`allowUnarmedBootstrap:true` と有限の範囲を明示できます。通常の剣必須条件を全体で解除する設定ではありません。経路管理と別の移動・採掘処理を同時に開始しないでください。

待機保護は `POST /action` の `{"group":"safety","method":"start","args":[]}` で明示的に有効にします。既存の行動中と終了直後はその行動へ制御を譲り、平穏な閉鎖済み小屋では待機します。実際の被ダメージを確認した場合は、予測上の小屋内表示だけで無視しません。使える剣・地形・単体近接敵を確認して有限の自衛を行い、実在庫の土が2個以上あれば開いた小屋を閉じます。

待機中の危険には、既知の乾いた足場を使い、1回4秒以内の退避を最大4回まで試みます。新しい危険や被ダメージを受信すると退避を見直します。ホストはオンライン危険通知を受けるたびにその時点の状態を記録し、接続を保持したまま保護と復帰の処理を呼びます。待機保護を明示的に停止する場合は `safety.stop` を使います。

同じ危険理由のログは5秒ごとにまとめて表示し、続報には省略件数を添えます。理由、接続、次元、生存回が変わったとき、直前に受信した体力から低下したとき、復帰に失敗したときはすぐに表示します。このログ変更を反映するにはBot本体を再起動してください。

## 露天掘りモード

指定したチャンクを上の層から順に、ワールドの最下層(既定)または指定の高さまで掘り下げます(仕様書 v1.2 第1〜4段階)。ターミナルでは次のように使います。

```
/quarry plan here chest=10,64,-3          # 今いるチャンク。保管チェストの座標を指定
/quarry plan 2 -1 bottom=40 chest=10,64,-3 # チャンク(2,-1)を高さ40まで
/quarry plan 0 0 1 1 combat=off            # チャンク(0,0)〜(1,1)の4チャンク、戦闘連携なし
/quarry start                              # 計画が ready のときだけ開始
/quarry status                             # 進み具合・保留・台帳
/quarry pause | resume | stop | cancel
/quarry accept                             # 一時停止の理由を確認したあと、残す例外を手動で受け入れる
/quarry load <jobId>                       # .local/quarry/<jobId>.json から再読み込み(再起動後)
```

`plan` は世界を変えずに範囲・最上段・保護ブロック・止水セルを調べ、`issues` が空のときだけ `start` できます。収納には手持ちの容器または登録済みの収納先を使います。API からは `POST /action` に `{"group":"quarry","method":"plan","args":[{...}]}` の形で同じ操作を呼べます(`plan` の引数は仕様書の設定 JSON)。

- 新規ジョブは道具の耐久を1回分だけ残します。残り2ならあと1回掘れます。残り1または耐久未確認の道具は使わず、代わりが必要な場合は道具待ちで一時停止します。
- まとめて掘る数は、最大8ブロックかつ「受信した残り耐久－予備」の範囲です。既定では残り9以下になると、毎回の採掘前に持ち物をサーバーから取り直して回数を決めます。採掘中でも耐久が予備まで減ったことを受信したら、その道具での採掘を止めます。
- 旧ジョブで明示した予備設定は引き継ぎます。既存ジョブを残り1まで使う設定に変える場合は、`IDLE` または一時停止が完了した `PAUSED` 状態で、`POST /action` に `{"group":"quarry","method":"configureTools","args":[{"reserveMinUses":1,"reserveFraction":0,"returnUses":0}]}` を渡します。
- 鉱石・コンテナ・スポナー・スカルク・不審な砂利・レッドストーン・虫食いブロックなどは壊さず保留にします。拠点・トンネル床・携帯拠点として守っているセルも壊しません。
- 水と溶岩は丸石などで塞ぎます。大きな液体だまり(12セル超)は一時停止します。範囲の外周1ブロックには止水用の設置だけを許します。
- 体力70%で退避、40%で緊急退避、90%まで回復してから再開します。満腹度が16未満なら食べます。
- 戦闘連携は、近接10m・クリーパー16m・遠距離24mより近い敵だけを相手にし(離脱は12/20/28m)、中断した位置から水平8m以内でだけ戦います。敵がいない状態が3秒続き、体力90%・満腹度18以上になってから掘削へ戻ります。`/auto` を使っていなくても、露天掘りの実行中だけ戦闘が有効になります。
- 新しい計画は階段用のセルを確保せず、各層を掘り進めます。旧計画を読み込むと、移行時点の最深層より上にある旧階段を残置扱いにし、記録された最深層から作業を再開します。
- 進行は1回の採掘ごとに `.local/quarry/<jobId>.json` へ保存します。行動コードの再読み込みでは一時停止して新しいコードで自動再開します。死亡・切断では一時停止し、`/quarry resume` で状態を照合してから続けます。
- 露天掘りの実行中は自律実行と手動操作を止めます。`/stop` は露天掘りも一時停止します。

### 下端から地上へ戻る

Botは採掘前に、掘削範囲に隣接するチャンクの端から安全な脱出列を1本予備選定し、土と道具耐久を確保します。各層の開始時に再検査し、下端の採掘・最終回収・収納後も同じ列を再確認してから脱出します。予備選定は実際の採掘・着地の証拠ではありません。新規ジョブでは `exit.side` の既定値 `auto` を使い、東・西・北・南の順に優先して各側最大16本の候補を調べます。たとえば東側の候補がすべて砂利・溶岩・保護領域にかかる場合は、西側以降から探します。`east`・`west`・`north`・`south` を指定すると、その側だけを調べます。

候補の比較には受信した地形を使います。最終確認や脱出列の選定に必要な地形が未受信なら、`subchunk_request` で読み込みを最大2回要求し、届いたブロック情報で再評価します。要求を送っただけでは地形を既知にしません。入口・頭上・地上の着地点を確認できた列だけを採用し、その1列の頭上を通常採掘で開けながら、足元に土を積んで1段ずつ登ります。安全な列を確認できない場合や途中で危険を検知した場合は一時停止し、理由を `/quarry status` に表示します。

脱出用の土は収納や他の施工に使わず保持します。列の選定前は192個が確保目安です。選定後は、計画した段数に予備8個を足した数が必要です。足りなければ `EXIT_MATERIAL_MISSING` で停止するので、表示された不足分を補ってから `/quarry resume` を使います。

各段は、サーバーで土ブロックが更新され、手持ちの土が1個減り、Botの足元が予定の高さにあることを確認した時点で確定します。Realmから各段の位置更新が届かない場合は、このサンドボックスのオペレーター権限で `/testfor @s[x=...,y=...,z=...,r=0.12]` を使い、予定の足元から半径0.12ブロック以内にBotがいるかを照会します。同じ接続・次元・生存回で、要求のUUIDが一致した `command_output` がBot自身の一致を返した場合だけ位置の証拠にします。照会結果は受信済みの位置とは別に記録します。通常の脱出にはジャンプ、採掘、土の設置を使います。

`/quarry status` の `egress.miningCompleted` は採掘の完了、`egress.surfaceReturned` は地上への復帰確認です。保留箇所を残す例外は内容を確認して手動で受け入れます。

一時停止中のジョブでは、診断用の `quarry.testPillar` で現在の足元に土を1〜3段積めます。2026年11月5日の実Realm検証では、通常のジャンプと設置で3段連続して登り、各段のブロック更新・土1個の消費・位置照会の成功を確認しました。検証後はデバッグ用の `/tp` で元の位置へ戻し、検証で置いた土4個を通常採掘で回収しました。サーバーから届いた持ち物で土が192個に戻ったことも確認しています。

### 手持ちの容器への収納

搬入が必要になったときは、次の順で手持ちの容器を使います。

1. シュルカーボックスがあれば、近くの確認済みの足場に設置して収納し、中身を保持した箱として回収します。
2. チェストが2個以上あれば、2個を並べてラージチェストを作り、収納後もその場に残します。
3. チェストが1個なら、通常のチェストを設置して収納し、その場に残します。
4. 使える手持ち容器がなければ、登録済みの収納先と従来のチェスト増設処理を使います。

工具・食料・非常用資材・手持ちの箱は保持します。満杯のシュルカーは回収して次の候補へ進み、箱の中へ別のシュルカーを入れません。常設チェストとその支持床・操作用の足場は保護します。

ラージチェストは2個のブロックを置くだけで完了にせず、同じ向きへの設置とサーバーからの54枠の受信を確認します。シュルカーの回収は、自分で設置した箱の破壊確認に加え、持ち物に戻った箱の27枠分の中身が一致したときだけ完了します。通常のコンテナを壊す処理はありません。

収納回収の最終確認に失敗した場合は、箱数・新規ID・内容受信・27枠一致を条件別に記録し、受信時刻と内容差分を残します。箱の回収確認条件や保存した比較基準は変更しません。工具補給が戦闘で中断された場合は、最新の全持ち物と開き直した箱から、同じ内容の工具が一意に移動したことを確認できる場合だけ再開します。耐久やNBTが変わって追跡できない場合は未確認のまま停止します。

シュルカー設置直後に空いた持ち物枠へ採掘物が自然取得された場合は、設置と消費を確認した時点の受信証拠を保持して照合します。元の箱の個体が手持ちから消費され、他の箱が保持されていることと、設置した箱の中身を確認してから収納を始めます。受信証拠のない過去の未確認設置を、後から成功扱いにはしません。

収納の送信元が自然取得で変化し、サーバーから送信元検証拒否（status 49）が返った場合は、その要求・スロット・内容・接続を固定して記録します。新しい持ち物全体と開き直した箱27枠が、拒否された要求の前から変わっていない箱の内容を証明できる場合だけ、転送実績を増やさず残作業をやり直します。自動再試行は同じ収納操作で最大2回に制限し、証拠不足・内容変化・他の拒否理由では停止を維持します。

設置・収納・回収の途中段階を保存し、再読み込み後も未完了の収納を先に処理します。接続・生存状態が変わった場合や、操作結果を確認できない場合は、重複設置・二重転送・別の箱の破壊をせず一時停止します。近傍の上下2段まで候補を探しますが、未知の地形や実経路を確認できない場所は使いません。

一時停止中に収納だけ1回実行する場合は、`POST /action` で `{"group":"quarry","method":"storeCarried","args":[]}` を指定します。検証などで数量を絞る場合は `args` に `{"deposits":[{"slot":14,"name":"minecraft:cobblestone","count":8}]}` を渡せます。受信した持ち物と保持方針の範囲を超える指定は拒否し、終了後は一時停止を維持します。

掘り抜きを優先する場合は、`POST /action` に `{"group":"quarry","method":"configureStorage","args":[{"pickupMode":"passive","depositWhen":"full"}]}` を渡せます。実行中の変更は、未完了の収納・補給を終えた安全な切替点で反映します。この設定では普通の採掘物を拾うための移動をせず、採掘や移動中に自然に入った分だけを保持し、受信した持ち物の全36枠が埋まったときに収納します。期限・層移動・最終段階でも普通のドロップを追わず、拾い残しは完了を妨げません。満杯でない終了時の資材は手持ちに残し、収納済みとは表示しません。自分のシュルカーや補給箱の回収確認、道具・地形の安全条件は維持します。従来の回収・容量方針へ戻す場合は `{"pickupMode":"active","depositWhen":"capacity"}` を指定します。

## 露天掘り・戦闘の効率化（2026-11-05）

- 採掘は受信したブロック更新でも完了を確認し、次の対象へ進みます。100msの監視は異常検知用に残しています。
- 戦闘後の初回採掘では道具を選び直します。ホットバー選択の送信は `selectionSent` で表し、サーバー確認済みとは扱いません。採掘・食事・設置などの成果は、それぞれの受信結果で確認します。
- 露天掘りは同じ層の少数候補を比較し、歩行距離に対して多く掘れる場所を選びます。洞窟天井などでは従来の順番を保ち、回収は実経路と期限を考慮します。最大8ブロック、回収期限、保護セル、道具耐久、安全待機・回復条件は維持します。
- 状態取得とレシピ一覧の生成を分離し、同じ判断内の弓の事前確認を再利用します。通常近接では不要なジャンプ予測を行いません。戦闘の50ms周期と交戦方針は維持します。
- 経路探索・射線候補の走査・表示用残数集計は途中で他の処理に実行を渡します。`quarry.counts` は初回集計中に `null` になり、その後はキャッシュを更新します。表示用の集計を完了判定には使いません。

観測用処理・診断処理・射線位置探索は個別モジュールへ分離しています。CPU計測と状態別計測の既存APIは維持しています。`host.js`・`state.js`・`entities.js` の変更を含むため、この更新をすべて有効にするにはBotの再起動が必要です。

速度比較は同じ地形・道具・在庫で行い、サーバー確認済みの採掘数・回収数・搬入数と、移動距離・戦闘からの復帰時間を確認します。模擬環境の歩数削減や局所ベンチマークは、実Realmの速度改善率やゲーム内の達成証明とは別です。

## 確認状況と現在の限界

接敵時は戦闘への移行を最優先します。採掘・収納・食事・回収・ベッド準備を中断し、片付けや防具交換の完了を待たずに戦闘へ移ります。防衛は接続中に既定で有効で、露天掘りが一時停止しても維持されます。戦闘が終わっても、手動停止や未解決の収納を理由なく再開しません。作業停止中の通常追跡は固定した地点から水平8m以内です。

迎撃するのは、近い可視接触・受信した接近や起爆準備を確認でき、敵からBotへの攻撃経路がある相手です。遠方や地形の向こうにいるだけの敵では作業を中断しません。弓の射線が通らない場合も射線探索のために移動せず、採掘を続けます。

木剣の試験では、原木2個 → 板材8個 → 作業台1個・棒4個 → 作業台を `(-27, 72, 21)` に設置 → 木剣1本、までを実持ち物で確認しました。その後、石剣と土小屋、鉄のツルハシまで進めています。記録は `.local/wooden-sword-proof.json`、`.local/stone-sword-proof.json`、`.local/safe-hut-final-proof.json`、`.local/iron-pickaxe-proof.json` に保存しています。これらは達成時の記録であり、現在の体力や所持数は `/status` で確認します。

正常な拾得がサーバーの通常の `inventory_transaction` で通知されることを実地確認し、その持ち物更新を保持・再適用するキャッシュ処理を修正しました。回収が一度成功したことと、長時間安定して資材を集め続けられることは分けて検証しています。

物理予測には実験的な Bedrock 対応 fork を使っており、vanilla と完全には一致しません。ジャンプ、段差、水際、補正後の継続移動は調整中です。潜水、高速水泳、乗り物、エリトラには対応していません。敵への対処や回収の失敗で死亡する問題も残っています。

## 困ったとき

- 接続先が見つからない場合は、Bot 用アカウントへの招待・承認、Realm ID、通常のゲームから参加できるかを確認します。
- 動かない場合は `/status` の `agent.reason`、`health`、`shelter`、`movement`、`inventoryConfidence` を確認します。失敗が続いた時の停止は、目標達成とは別です。
- 資材が増えない場合は、予測位置・ドロップ表示と実インベントリを区別します。現在はこの回収経路を重点的に検証しています。
- コード更新が反映されない場合は `hotReload.lastError` と監視対象を確認します。設定や安定層の変更は再起動が必要です。
- 再接続が上限に達した場合は、終了理由とネットワーク・設定を確認してから起動し直します。

通信基盤は [bedrock-protocol](https://github.com/PrismarineJS/bedrock-protocol)、通信仕様は [Mojang の公式資料](https://github.com/Mojang/bedrock-protocol-docs)、物理予測は [Bedrock 対応 draft](https://github.com/PrismarineJS/prismarine-physics/pull/152) を参照しています。

## 2026-11-07 レビュー対応

所属Realmの固定、停止と再開の排他、保存失敗の可視化、採掘前の脱出確認、ログ処理の上限制御とCIを追加しています。`STOPPING` または保存失敗中は再開できません。Bot本体とダッシュボードの再起動が必要です。移行・保存再試行・検証範囲は [レビュー対応記録](docs/review-hardening-2026-11-07.md) を参照してください。

`npm run test:review` は安全性回帰と関係する既存テスト、`npm run test:compare -- <base SHA>` は既存全件を基準版と比較します。既存失敗を含む比較の成功と、全テスト成功は別の結果です。
