# Minecraft Realms Bot

Minecraft 統合版の Realms に、別のプレイヤーとして参加する開発中の自動化 Bot です。接続を保ったまま行動コードを更新できます。

現在の目標は **拠点・武器の準備 → 食料と生存の確保 → 石のツルハシ・かまど・鉄 → 鉄のツルハシ → ダイヤモンド1個以上の実取得**です。実ワールドでは土の小屋の建築・閉鎖・退出・帰還、石剣、石のツルハシ、鉄3個の精錬と鉄のツルハシ作成を確認しました。ダイヤ取得はまだ達成しておらず、完成したサバイバル Bot ではありません。

## 起動

Node.js 24 以降と、対象 Realm に参加できる Minecraft 統合版用 Microsoft アカウントが必要です。普段のプレイヤーと同時に遊ぶ場合は、Bot 用の別アカウントを Realm に招待します。

```powershell
Set-Location G:\Projects\MinecraftBot
npm install
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
npm run auto
```

初回はターミナルに表示される Microsoft 認証ページでコードを入力し、Bot 用アカウントを選びます。普段のアカウントが自動表示される場合は、シークレット／InPrivate ウィンドウで開き直します。`REALM_ID` が空欄なら一覧から接続先を選び、`q` で取り消せます。

| コマンド | 動作 |
| --- | --- |
| `npm run auto` | 接続・初期ロード後に自律実行。異常終了時の再接続監視付き |
| `npm run auto:once` | 自律実行を1プロセスだけ起動。終了後の自動再接続なし |
| `npm start` | 接続してコード更新を監視。自律実行は `/auto` で開始 |
| `npm run realms` | 参加できる Realm の一覧を取得。ワールドへは入らない |
| `npm test` / `npm run check` | 自動テスト / 構文確認。ゲームの達成証明とは別 |

同じアカウントをゲーム画面と Bot で重ねて使う場合は、先にゲーム側を対象 Realm から退出させてください。

## 進捗画面

```powershell
npm run dashboard
```

同じPCで [http://127.0.0.1:3001](http://127.0.0.1:3001) を開きます。HTMLは `dashboard/index.html` です。1秒ごとにオンライン状態、足元座標、体力、持ち物、工程を更新します。狭い画面ではタブを切り替えます。

監視サーバーはBot本体と別に動き、Botの退出中も最後の確認値を表示します。画面は表示専用で、Botの操作用APIや認証情報は公開しません。作業の短い説明・履歴は `.local/mission-status.json`、表示用の最終確認値は `.local/dashboard-last.json` に保持します。

## 停止と再接続

| ターミナル入力 | 動作 |
| --- | --- |
| `/status` | 接続、体力、持ち物、行動、自律実行、コード更新の状態を表示 |
| `/auto` | 現在の観測と保持した進捗から自律実行を開始 |
| `/stop` | 自律実行と行動を停止し、接続を維持。ワールド内の時間は進む |
| `/reload` | 保存した行動コードを手動で反映 |
| `/quit`、`Ctrl+C` | 接続とプロセスを終了。自動再接続もしない |

`npm run auto` は `scripts/keep-alive.js` が子 Bot を監視します。**非ゼロの終了コードで異常終了した場合だけ**、待ち時間を2秒から指数的に増やして再接続します。初期設定は待ち時間最大60秒、10分間に再起動最大5回です。上限に達すると停止します。

正常終了、明示した `/quit` や API の `/disconnect`、停止シグナルによる終了では再接続しません。`/stop` はプロセスを終了しないため、再接続も発生しません。行動コードの保存も接続を切り替える理由にはなりません。

## 設定

既存の `.env` を編集します。

| 設定 | 初期値・用途 |
| --- | --- |
| `BOT_PROFILE` | `main`。認証を分けるローカル名。別アカウントなら `bot` などへ変更 |
| `REALM_ID` | 空欄なら一覧選択。指定すればその Realm に接続 |
| `MINECRAFT_VERSION` | 空欄。現在の行動実装は `1.26.60` 用 |
| `API_PORT` | `3000`。同じ PC 内の API 待受ポート |

認証キャッシュは `.auth/<BOT_PROFILE>/` に保存します。パスワードを設定ファイルへ書く必要はありません。`.auth/`、`.env`、`.local/` は Git の管理対象外です。

## 自律実行の順序

1. 既知の土・草の斜面に小さな避難所を作るか、平地に土17個で壁と屋根のある小屋を建てる。実際の土の取得と消費を確認して入口を閉じ、外へ出る時は自分が施工した入口だけを開ける。
2. 原木約2個から板材・作業台・棒を用意し、まず木剣を作る。
3. 木剣を実際の持ち物で確認してから、木のツルハシ・石材を用意して石剣へ進む。既に材料があれば直接石剣を作る。
4. 石のツルハシ、かまど、石炭、鉄の原料と精錬を経て、鉄のツルハシを作る。摩耗した道具は交換を準備する。
5. 受信した地形にある鉱石へ、安全を確認しながら掘り進む。**サーバー由来の持ち物にダイヤモンド1個以上が入った時だけ最終完了**とする。

避難所の最初の目標は小さな閉鎖空間です。作業台・かまど用の3×2の部屋は将来の拡張として分け、未施工の領域を完成済みとは扱いません。木剣のプレビューや石材の達成だけでも最終完了にはなりません。

敵の接近、体力、食料、持ち物、地形を観測します。退避・自衛・狩り・食事の操作を実装していますが、生存を安定させる調整は継続中です。未知地形、未確認の持ち物、危険な施工、未実装機能、繰り返す失敗では待機または停止します。

## 接続を保ったコード更新と記録

接続を持つ `src/host.js` と、差し替える `src/runtime.js`・行動モジュールを分離しています。行動コードを保存するとホットリロードし、同じ接続の観測と持ち物を使って再開します。構文や初期化に失敗した変更は採用せず、旧コードを保持します。クラフト・設置などの途中では安全な切替点を待ちます。

安定ホスト、認証・通信の中核、依存ライブラリ、`.env` などの設定を変えた場合は必要に応じて再起動します。監視対象と適用世代は `/status` の `hotReload.watchFiles` / `generation` で確認できます。

避難所と土小屋の施工 memo はホットリロードを跨いで保持します。新しいホストで起動すると、`.local/mission-memory.json` に記録を保存し、接続先の Realm・プロファイル・次元が確定してから復元します。既に進行中の記録を上書きせず、途中で接続や処理世代が変わった読込結果も採用しません。終了時には保存待ちを行います。古いホストを接続したまま行動コードだけ更新した場合、ディスク連携は次回起動から有効です。

記録の保存・復元は結合テストまで確認しており、自然切断からの一連の自動復帰は実地検証中です。復元した記録だけで安全や完成を認定せず、現在の壁・屋根・入口を再確認します。未確認の設置や回収は成功記録へ昇格しません。

移動の予測位置と最後に受信したサーバー位置は分けて扱います。回収・クラフトは実際の持ち物の変化、採掘は受信した空気、設置はブロックと消費の両方を確認します。ドロップの消滅や予測上の到着だけでは取得成功としません。

## ローカル API

同じ PC の `http://127.0.0.1:3000` で利用します。POST は JSON と `Content-Type: application/json` が必要です。

```powershell
$base = 'http://127.0.0.1:3000'
Invoke-RestMethod "$base/status"

# 自律実行の開始
$body = @{ objective = 'diamond'; diamondCount = 1 } | ConvertTo-Json
Invoke-RestMethod -Method Post -ContentType 'application/json' -Body $body "$base/agent/start"

# 行動停止。接続は維持する
Invoke-RestMethod -Method Post -ContentType 'application/json' -Body '{}' "$base/agent/stop"

# 読み取り用の拠点候補プレビュー
$body = @{ group = 'shelter'; method = 'preview'; args = @(@{ radius = 8 }) } | ConvertTo-Json -Depth 8
Invoke-RestMethod -Method Post -ContentType 'application/json' -Body $body "$base/action"
```

| API | 用途 |
| --- | --- |
| `GET /status`、`GET /blocks?radius=1` | 状態・受信した地形の確認。`known:false` を空気扱いしない |
| `POST /agent/start`、`/agent/stop`、`/agent/tick` | 自律実行の開始・停止・1回の判断 |
| `POST /reload`、`/disconnect` | コード更新 / 明示的な終了 |
| `POST /move/preview`、`/move/start`、`/move/stop` | 経路移動。目標の `y` は足元 |
| `POST /mining/preview`、`/mining/start`、`/mining/stop` | 整数座標のブロック採掘 |
| `POST /craft/preview`、`/craft/start`、`/craft/open`、`/craft/close` | 受信済みレシピによるクラフト |
| `POST /combat/attack`、`/combat/defend`、`/combat/stop`、`/respawn` | 自衛、停止、正規リスポーン |

追加機能は `POST /action` の `{ "group": "...", "method": "...", "args": [...] }` で呼び出します。`execute` などは実際にワールドや持ち物を変更します。

| group | 主な method・用途 |
| --- | --- |
| `shelter` | `preview` / `execute` / `leave` / `snapshot` / `stop`。斜面の避難所の施工と退出 |
| `hut` | `preview` / `execute` / `leave` / `snapshot` / `stop`。平地の土小屋の建築・閉鎖・退出 |
| `guardRoute` | `execute` / `returnRoute` / `escape` / `snapshot` / `stop`。装備・敵・被ダメージを監視する経路移動と退避 |
| `safety` | `start` / `stop` / `snapshot`。待機中の自衛・小屋閉鎖・退避不能時の非常停止。初期状態は無効 |
| `interactions` | `previewPlace` / `placeBlock` / `openFurnace`。作業台・かまど・土・床置きたいまつの正規設置と使用 |
| `food` | `preview` / `eat` / `snapshot` / `stop`。実際の食料を食べる |
| `foraging` | `preview` / `execute` / `snapshot` / `stop`。食料用動物の追跡・狩り・回収 |
| `combat` | `preview` / `attack` / `previewEngage` / `engage` / `stop`、`previewHunt` / `hunt`。剣による限定時間の自衛と食料用の狩り |
| `inventory` | `equip`。アイテムをサーバー確定の選択スロットへ移す |
| `furnace` | `putInput` / `putFuel` / `takeOutput` / `snapshot`。投入・燃料・精錬結果の受領 |
| `prospecting` | `start` / `snapshot` / `stop`。受信した地下地形から鉱石を探す |
| `excavation` | `preview` / `execute` / `snapshot` / `stop`。隣の1セルを同高・1段上・1段下へ掘って移動 |
| `tunneling` | `preview` / `execute` / `snapshot` / `stop`。確認済みの鉱石へ短い掘削工程を組む |

長い処理は状態を確認しながら扱います。入力を送ったこと、時間が経過したこと、プレビューが通ったことだけでは成果になりません。

`guardRoute` の座標は足元です。通常は実所持の剣を装備してから動き、最初の被ダメージや危険な敵を確認すると資源への移動を中断します。 出発時の体力下限は既定14で、剣を確認できる食料・道具の準備に限り `minimumOutwardHealth:10` を明示できます。初回被ダメージ時の中断は維持します。`visitedPrefix` は同じワールドで実際に通った順序の足元座標であり、計画だけの地点を渡してはいけません。`returnRoute` はその逆順へ戻り、小屋の入口付近が帰着点の時だけ、現在の小屋を確認して閉鎖します。

現在すでに敵が近い時に安全域へ離れる用途は `escape` です。全経路が確認済みで、敵から離れる場合だけ緊急移動します。明示した `escape` では、未武装でも `maxLegDistance:12` まで指定し、確認済みの経路を連続移動できます。通常の未武装移動は1区間2ブロック、未武装の明示指定の上限は64地点・指定地点間の距離48ブロックです（既定は8地点・12ブロック）。Nav内部の迂回を含む実際の歩行距離とは区別します。走行は実際の空腹値と足場が許す区間に限ります。到着しても `safe:true` や小屋への帰還に置き換えず、`escaped`・`riskRemains`・現在の敵と位置の確度を確認します。失敗理由は `GET /status` の `guardRoute.routeRejection` に残ります。元の移動中断は `routeInterruption`、帰着後の小屋閉鎖は `refugeClosure` として別々に記録します。実行APIは終了まで待つため、クライアント側のタイムアウトを実行時間より長くしてください。

未武装で最初の木材を採る場合だけ、`allowUnarmedBootstrap:true` と有限の範囲を明示できます。通常の剣必須条件を全体で解除する設定ではありません。経路管理と別の移動・採掘処理を同時に開始しないでください。

待機保護は `POST /action` の `{"group":"safety","method":"start","args":[]}` で明示的に有効にします。既存の行動中と終了直後はその行動へ制御を譲り、平穏な閉鎖済み小屋では待機します。実際の被ダメージを確認した場合は、予測上の小屋内表示だけで無視しません。使える剣・地形・単体近接敵を確認して有限の自衛を行い、実在庫の土が2個以上あれば開いた小屋を閉じます。

待機中の危険には、既知の乾いた足場を使い、1回4秒以内の退避を最大4回まで試みます。途中で敵が残る場合も、実際に移動でき、同じ敵で被ダメージがない時だけ続けます。新しい危険や被ダメージで中止し、現在の敵から離れたことを確認できない場合は、一度だけローカル `/disconnect` を呼んで非常停止します。理由コード・体力・接続範囲の一致をログに残します。正常終了なので異常終了監視による即時再接続は行いません。コードの保存・反映では接続を維持します。資源作業の停止と待機保護の設定は別で、保護を完全に止める場合は `safety.stop` を呼びます。

## 露天掘りモード

指定したチャンクを上の層から順に、ワールドの最下層(既定)または指定の高さまで掘り下げます(仕様書 v1.2 第1〜4段階)。ターミナルでは次のように使います。

```
/quarry plan here chest=10,64,-3          # 今いるチャンク。保管チェストの座標を指定
/quarry plan 2 -1 bottom=40 chest=10,64,-3 # チャンク(2,-1)を高さ40まで
/quarry plan 0 0 1 1 combat=off            # チャンク(0,0)〜(1,1)の4チャンク、戦闘連携なし
/quarry start                              # 計画が ready のときだけ開始
/quarry status                             # 進み具合・保留・台帳
/quarry pause | resume | stop | cancel
/quarry accept                             # 階段などの例外を受け入れて完了扱いにする
/quarry load <jobId>                       # .local/quarry/<jobId>.json から再読み込み(再起動後)
```

`plan` は世界を変えずに範囲・最上段・階段・保護ブロック・止水セルを調べ、`issues` が空のときだけ `start` できます。チェストを指定しない場合は持てる分だけ掘り、持ち物が埋まると `WAITING_FOR_STORAGE` で一時停止します。API からは `POST /action` に `{"group":"quarry","method":"plan","args":[{...}]}` の形で同じ操作を呼べます(`plan` の引数は仕様書の設定 JSON)。

- 1回の採掘は最大8ブロック。道具は残り耐久の予備(最大値の10%か8回の多い方)を割らない範囲だけ使い、足りない時は道具待ちで一時停止します。
- 鉱石・コンテナ・スポナー・スカルク・不審な砂利・レッドストーン・虫食いブロックなどは壊さず保留にします。拠点・トンネル床・携帯拠点として守っているセルも壊しません。
- 水と溶岩は丸石などで塞ぎます。大きな液体だまり(12セル超)は一時停止します。範囲の外周1ブロックには止水用の設置だけを許します。
- 体力70%で退避、40%で緊急退避、90%まで回復してから再開します。満腹度が16未満なら食べます。
- 戦闘連携は、近接10m・クリーパー16m・遠距離24mより近い敵だけを相手にし(離脱は12/20/28m)、中断した位置から水平8m以内でだけ戦います。敵がいない状態が3秒続き、体力90%・満腹度18以上になってから掘削へ戻ります。`/auto` を使っていなくても、露天掘りの実行中だけ戦闘が有効になります。
- 出入り用の螺旋階段は最後まで残すため、通常は `UNRESOLVED_EXCEPTIONS` で一時停止します。内容を確認して `/quarry accept` で完了(`COMPLETED_WITH_EXCEPTIONS`)にします。
- 進行は1回の採掘ごとに `.local/quarry/<jobId>.json` へ保存します。行動コードの再読み込みでは一時停止して新しいコードで自動再開します。死亡・切断では一時停止し、`/quarry resume` で状態を照合してから続けます。
- 露天掘りの実行中は自律実行と手動操作を止めます。`/stop` は露天掘りも一時停止します。

## 確認状況と現在の限界

| 対象 | 実ワールドで確認できた範囲 |
| --- | --- |
| Bot 用別アカウントの認証・Realm 参加 | 確認済み。位置・体力・地形などの受信を確認 |
| 短距離移動・拠点候補への接近 | 確認済み。補正と再計画が多く、安定性は改善中 |
| 原木の破壊・回収 | 過去の試験で原木の実取得、原木2個から木剣の製作を確認。連続生存と安定した自律回収は改善中。現在の所持品は `GET /status` で確認 |
| 避難所の初期掘削 | 土4ブロックの破壊を確認。閉鎖前に死亡し、その後クリーパーによって旧候補地が破損 |
| 斜面の避難所の閉鎖・退出・部屋拡張 | 実行器・テストあり。旧候補地は破損。部屋拡張は未施工 |
| 平地の土小屋 | 土17個の壁・屋根・入口、足場の回収、退出と帰還・再閉鎖を確認。中心は `(-9, 67, 11)` |
| 木剣 | 原木からの製作と再取得を確認。木剣だけでの長時間生存は未安定 |
| 木のツルハシ・石剣 | 実ワールドで製作・実際の持ち物への追加を確認 |
| 石のツルハシ・かまど・精錬・鉄のツルハシ | 実際の鉱石採取、鉄3個の精錬、鉄のツルハシ製作と小屋への帰還を確認 |
| 自衛・狩り・食事 | 操作と安全判定を実装。継続交戦と安定した食料自給は実地検証中 |
| 正規リスポーン | 接続を維持し、復帰位置と体力20を確認済み |
| 接続を維持したホットリロード | 同じ接続ID・プレイヤーIDのまま行動コード更新を確認済み |
| 異常終了後の再接続・拠点記録復元 | 実装・テストあり。自然切断を含む長時間の実地検証は未完了 |
| ダイヤモンド1個以上の取得 | **未達。実持ち物による完了確認なし** |

木剣の試験では、原木2個 → 板材8個 → 作業台1個・棒4個 → 作業台を `(-27, 72, 21)` に設置 → 木剣1本、までを実持ち物で確認しました。その後、石剣と土小屋、鉄のツルハシまで進めています。記録は `.local/wooden-sword-proof.json`、`.local/stone-sword-proof.json`、`.local/safe-hut-final-proof.json`、`.local/iron-pickaxe-proof.json` に保存しています。これらは達成時の記録であり、現在の体力や所持数は `/status` で確認します。

正常な拾得がサーバーの通常の `inventory_transaction` で通知されることを実地確認し、その持ち物更新を保持・再適用するキャッシュ処理を修正しました。回収が一度成功したことと、長時間安定して資材を集め続けられることは分けて検証しています。

物理予測には実験的な Bedrock 対応 fork を使っており、vanilla と完全には一致しません。ジャンプ、段差、水際、補正後の継続移動は調整中です。潜水、高速水泳、乗り物、エリトラには対応していません。敵への対処や回収の失敗で死亡する問題も残っています。

## 困ったとき

- 接続先が見つからない場合は、Bot 用アカウントへの招待・承認、Realm ID、通常のゲームから参加できるかを確認します。
- 動かない場合は `/status` の `agent.reason`、`health`、`shelter`、`movement`、`inventoryConfidence` を確認します。失敗が続いた時の停止は、目標達成とは別です。
- 資材が増えない場合は、予測位置・ドロップ表示と実インベントリを区別します。現在はこの回収経路を重点的に検証しています。
- コード更新が反映されない場合は `hotReload.lastError` と監視対象を確認します。設定や安定層の変更は再起動が必要です。
- 再接続が上限に達した場合は、終了理由とネットワーク・設定を確認してから起動し直します。

通信基盤は [bedrock-protocol](https://github.com/PrismarineJS/bedrock-protocol)、通信仕様は [Mojang の公式資料](https://github.com/Mojang/bedrock-protocol-docs)、物理予測は [Bedrock 対応 draft](https://github.com/PrismarineJS/prismarine-physics/pull/152) を参照しています。
