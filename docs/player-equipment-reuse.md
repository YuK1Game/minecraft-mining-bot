# プレイヤーモードの設備の回収・再利用

プレイヤーモードで、自分が仮設した作業台・空のかまどを遠征先へ持ち回り、チェストを新設するときはラージチェストの完成まで確認する。拠点の固定設備は残す。実Realmでの連続運転は未確認で、以下は実装とオフラインの結合検証の記録。

## 修正した無駄と原因

| 原因 | 変更後 |
| --- | --- |
| 設置済みの作業台を「利用できる場所」として記録しても、自分が片付ける仮設物として管理していなかった | 設置時のブロック更新と持ち物の消費を結び付け、自分の仮設設備を別の台帳に記録する |
| かまどの準備などで次の材料を集めに出発し、準備に使った作業台が残った | 通常の遠方への移動・探索・採掘の前に、近くの自分の仮設設備を回収する |
| チェスト作成、旅行中の準備、旅行キットの処理が通常の片付けを経由しなかった | 作業の成功・失敗の両方で片付けへ接続し、回収できない場合は記録を残す |
| 所持品に設備がないことを見て、近隣設備の利用・回収より先に新しい材料を要求した | 使用できる既存設備、持参品、自分の仮設物の回収を先に判断し、その後に新規作成する |
| 帰還時の補充に作業台・かまど・チェストが含まれていなかった | 帰還・収納のついでに、作業台1個・かまど1個・チェスト2個まで不足分を取り出す。設備不足だけを理由とする新しい帰還条件は加えない |
| 新設チェストが1個だけでも収納先・拠点として扱われる経路があった | 2個分を確保してから置き、サーバーから54枠の中身を受信した時だけ完成とする |
| 途中で止まった片側を通常のチェストとして扱い、向きが変わった場所から2個目を置いた | 未完成の2マスを保存し、受信した向きに合う立ち位置から不足側を置く |

## 仮設設備の扱い

実装の中心は `src/modes/player-workstations.js`、`player-workstation-runtime.js` と `src/actions/station-recovery.js`。Runtime・自律計画・収納処理はこの共通処理へ接続する。

1. **設置の確認:** 実際の設置操作の受信記録から、対象ブロック、消費前後の持ち物、ワールド、接続、ライフ、リクエストIDを照合する。観測しただけの作業台や、拠点の設計図にある固定設備は自分の仮設物として登録しない。
2. **作業中の再利用:** 同じ場所で続けてクラフトする間は設備を利用する。設備への接近や設置準備を、出発時の回収で置き換えない。
3. **出発前の回収:** 通常の遠方への作業へ移る前に、近くの所有記録がある設備を候補にする。戦闘、食事、避難、停止などの判断を上書きしない。自律処理では通常の作業許可の引き継ぎを通す。
4. **破壊の確認:** 正しい設備、現在の所有記録、接続・ライフ、回収可能な所持枠を確認して通常の採掘を行う。破壊したと数えるのは受信した空気だけ。
5. **拾得の確認:** 同じ回収操作中に設備アイテムが所持品へ増えたことを受信して完了にする。歩いた、ドロップが消えた、ブロックが空気になったという情報だけでは回収完了にしない。
6. **中断・失敗:** 回収途中の記録を `.local/player-workstations.json` に残す。拾得待ちは再開時に二重採掘しない。失敗後は間隔を置き、同じ回収を無制限に連続実行しない。再接続・死亡後の別の所持品増加を、以前の拾得の成功には使わない。

空のかまどの回収では、対象のかまどを開いて入力・燃料・出力の3枠が空であることを受信し、燃焼中ではないことと有効なツルハシを確認する。内容がある・燃焼中・内容不明のかまどは壊さず、既存設備として利用する。内容物を自動で全回収して空にする機能は今回の対象に含めていない。

回収できた設備の座標は、同じワールドの設備候補と作業場所の記憶から外す。別ワールドの記録は消さない。回収済みの設置記録をもう一度渡しても、所有権を復活させない。

所有権は設置時の受信記録と現在のブロック情報を照合するもの。ブロックのruntime ID自体は個体識別子ではない。破壊や置き換えを受信した場合は所有権を失効させるが、未観測の間に完全に同じブロックへ置き換わった事実まで判別する仕組みではない。

## ラージチェストの成立条件

実装は `src/modes/player-storage.js`、`player-chest-pairs.js`、`src/modes/house/house-large-chests.js`。

- 既存のラージチェストに空きがあれば再利用する。
- 既存の単体チェストを利用する場合は、隣へ1個追加して54枠を確認する。受信した向きが不明な単体チェストには、推測で2個目を置かない。
- 新しい場所ではチェスト2個を持ってから設置を始める。1個分の材料しかない場合は、片側だけを新設しない。
- 予約した2マスと未確認の設置段階を `.local/player-chest-pairs.json` に保存する。片側設置後の中断は、その組の不足側を完成させる。送信した可能性のある設置を、まだ空気に見えることだけで再送しない。
- 隣接したチェスト2ブロックだけではラージチェストと断定しない。開いた容器の54枠を受信できなければ、収納成功・拠点完成として扱わない。
- 家の設計図にあるラージチェスト2組も同じ54枠の確認を必要とする。片側設置中・未確認の組は、帰還先の候補から除外する。

2個の設置はサーバー上で別々の操作なので、中断時に片側だけが残ることはある。その状態を完成扱いせず、続きを行うための記録を保持する。

## 検証

主要な結合検証は `test/player-workstations.test.js`。実 `createInteractions` の設置記録、Runtimeの操作窓口、実採掘処理、受信したInventoryStoreの更新をつなぎ、同じ作業台1個を別の作業場所で繰り返し使えることを確認する。通信相手と移動の物理は模擬環境であり、実Realmの達成とは区別する。

`test/player-workstation-autonomy.test.js` は実観測・計画・自律tickから回収処理への到達と、戦闘時の優先順位、作業許可の引き継ぎを確認する。所有権・炉の中身・回収中断は `player-workstation-ownership.test.js` と `station-recovery.test.js`、不足分の補充は `player-workstation-restock.test.js` で確認する。チェストは `player-large-chest.test.js`、`house-large-chests.test.js` と既存の帰還・建築検証で、材料不足・片側中断・向き・27枠の拒否・54枠の成立を確認する。

実Realmで残る確認は、通信遅延や位置補正を含む遠征での連続回収、満杯の所持品から収納して回収する流れ、片側設置後の再接続と54枠の受信。テスト合格だけでこれらを確認済みとはしない。
