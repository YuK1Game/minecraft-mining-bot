# 戦闘モード仕様書

対象: HouchiChan（統合版 1.26.60 Bot）の自律戦闘
作成: 2026-11-04（JST）。2026-11-02〜04 の変更をすべて反映した現行仕様。
数値はすべてコードの既定値（括弧内は定義場所）。

---

## 1. 全体の流れ

```
敵を検知 → 候補の選別 → 戦闘の開始（制御権の取得） → 戦い方の選択 → 攻撃 → 終了・再判定
```

接続中の防衛は既定で有効とし、露天掘り・旧自律作業の実行状態とは独立させる。接敵時は採掘・収納・食事・回収・ベッド準備を中断し、戦闘への制御権移行を最優先する。中断した作業のdrain・保存・防具交換を待って戦闘開始を遅らせない。古い作業の後片付けから新しい戦闘入力を停止しない。

迎撃対象には、現在の攻撃アクセスと認識の観測根拠を要求する。地上敵は敵からBotへの歩行経路、射撃・飛行敵は現在の射線を確認し、近距離の可視接触、直近の接近運動、起爆準備などを評価する。敵AI内部の標的を直接取得したという意味ではない。Botから敵へ下りられるだけで、敵が逆に登って攻撃できるとは判断しない。遠方、遮蔽、経路不明を作業中断の許可にはせず、不明を安全と断定することもしない。

接敵前に送信済みだった持ち替え・収納・クラフト要求は、戦闘が操作権を保持したまま実応答を照合する。応答待ちは戦闘の `preparing` 状態で、武器操作だけを保留し、一般のBUSYとして戦闘を解除しない。実応答後に画面を閉じ、必要なら戦闘所有者に限定した安全な再同期で新しい持ち物全体を受信してから攻撃する。未確認の内容を推測で既知に戻さず、接続・生存回の変化や確認期限超過では停止する。

露天掘りがエラーや手動操作で一時停止しても防衛は維持し、戦闘終了だけで作業を再開しない。作業停止中は接続・生存回に結び付けた固定防衛地点を使い、通常追跡移動は水平8m・上下1.5m以内の経路とする。範囲外への追跡を拒否しても、現在接触している敵への戦闘移行は妨げない。緊急退避は距離制限の対象外。死亡・未参加・実際の睡眠中など、入力できない状態の確認は維持する。診断用に戦闘を明示停止する場合は `userBehaviors.stop`、再開は `userBehaviors.start` を使う。

| 段階 | 内容 | 主な実装 |
|---|---|---|
| 検知 | サーバーから届くエンティティ情報で、32m以内の敵対モブを把握する | `src/entities.js`, `src/threats.js` |
| 候補の選別 | 敵ごとのプロファイル、HP、経路、射線から、いま戦う相手を1体選ぶ | `src/combat-coordinator.js`（`selectCandidate`） |
| 戦闘の開始 | 採掘・建築・食事などの作業を止め、入力と移動の制御権を取る | `src/runtime.js`（`acquireUserControl`） |
| 戦い方の選択 | 剣・弓・接近・回避のどれかを、毎回の判定（50ms）で選び直す | `src/combat-coordinator.js`（`fight`） |
| 攻撃 | 剣の連打、弓の引き絞りと発射 | `src/melee-combat.js`, `src/ranged-combat.js` |
| 終了 | 撃破（サーバーの死亡通知で確認）、標的の消失、中断理由のいずれかで終了し、作業に戻る | 同上 |

- 判断の周期は **50ms（1tick）**（`runtime.js` のタイマー、コーディネータの `pollMs = 50`）。
- 1回の戦闘の上限は **120秒**（`durationMs`）。剣・弓の1回の実行単位は最大 **8秒**（`controllerSliceMs`）。
- 戦闘の開始時に、開いたままのインベントリ画面は閉じる。送信済みの持ち替え要求があれば、その完了を最大 **0.6秒** 待ってから開始する（途中で取り消すと持ち物が「不明」になるため）。

## 2. 戦う相手の選び方

### 2.1 対象になる条件（すべて満たすもの）
- 敵対モブで、生きていて、位置がわかっている（同じディメンション）。
- 距離が **32m以内**（`engageRadius`）。
- プロファイル（2.3）で交戦が許可されている。
- 歩いて近づくルートがある（3m以内の敵、およびクリーパーは不要。クリーパーは撃つだけで近づかないため）。
  - ルートは、足元から半径32mの「立てるマス」の塗りつぶしで判定する（`src/threat-reachability.js`）。計算は1回15msまで。
  - 15msで終わらない起伏のある地形では、近い敵3体に向けた狙い撃ちの探索（各10ms）で補う。
  - 地形のマス判定は、地形が変わるまで使い回す（地形に関係するパケットを受けたときだけ作り直す）。

### 2.2 優先順位
1. 剣の届く距離（**3.0m以内**）の敵
2. 回避すべきクリーパー
3. 弓で狙える敵（**6〜32m**）
4. 接近が必要な敵

同じ順位の中では近い順。同じ順位の相手を追っているあいだは、別の敵が **1.5m以上** 近くない限り標的を変えない（ヒステリシス）。

### 2.3 敵ごとのプロファイル（`src/combat-profiles.js`）

| 分類 | 対象の例 | 方針 |
|---|---|---|
| 必要なら交戦 | ゾンビ類、ハスク、クモ、ブレイズ、スケルトン類、ウィッチ、ピリジャー、ドラウンド、スライム類、ファントム、ヴェックスなど | 自分から倒しに行く |
| 特殊 | クリーパー、シュルカー | クリーパーは 4章のルールに従う |
| 近接のみ | エンダーマン | 弓は使わない。目を合わせない |
| 反撃のみ | ピグリン、ゾンビピグリン、アイアンゴーレム、オオカミ、ハチ等 | 直近5秒以内に被弾し、相手が4m以内にいるときだけ |
| 交戦しない | ウォーデン、ウィザー、エンダードラゴン、エルダーガーディアン、クリーキング等 | 戦わない（回避のみ） |
| 不明な種類 | 一覧にないもの | 安全とは見なさない |

### 2.4 再挑戦までの待ち時間（同じ相手）

| 終了の理由 | 待ち時間 |
|---|---|
| 通常の中断 | 0.4秒 |
| 接近できない（`APPROACH_NOT_READY` / `NO_READY_ACTION` / `NO_PROGRESS`） | 2秒から始まり、続くたびに倍（4・8・16秒が上限） |
| クリーパーの射線が作れない（`CREEPER_NO_SIGHT`） | 1秒から始まり、続くたびに倍（16秒が上限） |
| クリーパーの回避・接近中・点火関連 | 待たずにすぐ再判定 |

## 3. 戦い方

### 3.1 剣（近接）
- 距離 **3.0m以内** で剣を使う（`MELEE_SELECT_REACH`, `reach = 3.0`）。
- **連打**：攻撃の最短間隔は **100ms**（`cooldownMs`）。実測は中央値 **約180ms**。
- **ジャンプ斬り（クリティカル）は使わない**。着地待ちで連打が止まるため。統合版には攻撃クールダウンがない。
- 武器の持ち替え：ホットバー（1〜9番）にある武器はスロット選択だけで持つ。ホットバーにないときだけインベントリ経由で入れ替える。
- 叩いたノックバックで相手が3mを超えても、**4.5m以内なら最大2秒（40回の判定）** は交戦を終えず、相手が戻るのを待つ（`CLOSE_HOLD_RANGE`, `CLOSE_HOLD_POLLS`）。

### 3.2 弓（遠距離）
- 距離 **6〜32m** で弓を使う（`RANGED_SELECT_MIN`, `RANGED_SELECT_MAX`）。6m未満は剣のほうが速いので弓は使わない。
- **最大チャージで即発射**：引き絞り開始から **20tick（約1.0秒）** の時点で放つ。引き絞り中も照準を毎回更新する。
- **即次弾**：放った直後に次の引き絞りを始める。矢の発射確認（自分の矢の出現と、矢の数の減少）は裏で並行して行う。
- 実測：連射間隔 **1.15〜1.24秒**、出現から1射目まで **約1.3秒**（剣を持っていた場合も同程度）。
- 偏差撃ち：歩く敵の未来位置を狙う。スケルトン類（横に動いて向きを変える）は偏差を **半分** にする。
- 射線：空気と、当たり判定のないブロック（草・花・落ち葉・松明など）は通る。水・溶岩・未読込の地形は遮るものとして扱う。射線上の敵対モブは障害物にしない（当たっても問題ないため）。プレイヤーと友好モブは保護する。
- 引き絞り中に標的が倒れたとき：32m以内に射線の通る別の敵がいれば、引き絞ったまま照準を移して放つ。いなければ引き絞りを取り消し、矢を消費しない。
- 引き絞りの取り消しは剣（なければ空き・その他）へ持ち替えて行う。その後の引き絞りの前に、弓を選び直す（サーバーは自分の持ち替えを送り返さないため）。
- サーバーが引き絞りを拒否した場合はすぐ検知して撃ち直す（`DRAW_REJECTED`、1回の戦闘で3回まで）。
- 弓の耐久値の更新では「弓が変わった」と扱わない（種類とスロットが同じなら継続）。

### 3.3 射線が通らない場合
- 戦闘開始前の受動観測で `LOS_BLOCKED` の弓標的は選ばず、作業を中断しない。
- 射線を作るための移動・周回・反復探索は行わない。戦闘中に固定遮蔽を確認した場合も制御権を作業へ戻す。
- 既に交戦している移動標的への `SIGHT_STALE` は、従来の最大0.9秒・8回の猶予だけ再観測し、古い照準からの発射や接近に置き換えない。

### 3.4 接近
- 現在攻撃が届く敵に対し、射程外・矢切れでは許可された経路で接近する。弓の射線不通を理由に接近へ切り替えない。通常の追跡上限は40m（`maxChaseDistance`）、停止中の防衛・露天掘り中は別途8mの制限を適用する。
- 坂道では、上下3ブロックまで立てる高さを探して接近の足場にする。
- 他の敵（クリーパー以外）は半径 **2.5m** だけ避けて通る。クリーパーは本来の危険半径を避ける。

## 4. クリーパー

| 状況 | 動き |
|---|---|
| 3m以内（剣の届く距離） | 1回だけ叩いてノックバックさせ、離脱する |
| 3m〜8m（高低差1.5ブロック以上なら3m〜6.5m） | 回避（後退）。半径 9/10/8.5m の地点へ最大4回。9m以上離れたら完了 |
| 8m以上（高低差1.5ブロック以上なら6.5m以上） | 弓で撃つ。点火中は撃たずに回避する |
| 射線がない | 弓標的として作業を中断せず、射線探索のために移動しない（3.3）。実際の近接・起爆危険は別に監視する |

- **近づいてくる速さの判定**：クリーパー自身の動き（Botの方向への速度）だけで計算する。Bot自身の移動は含めない。
  - 引き絞りの開始には実距離8m（段差6.5m）を要求し、1.2秒先の予測距離が射撃を終える下限5mを割る場合は後退する（`CREEPER_CLOSING`）。開始前から着弾まで常に8mを維持する条件にはしない。
  - 引き絞り中は0.5秒先の予測距離が **5m**（爆発の範囲＋余裕）を下回るまでは撃ち切る（2026-11-05 変更。8mのままだと速いクリーパーには一度も撃てなかった）。
- **追い詰められた場合**（回避の逃げ先が見つからない `CREEPER_EVADE_UNAVAILABLE`）：そのクリーパーは10秒間「追い詰められた」扱いにする（2026-11-05 追加）。
  - 3m以内：1回叩いてノックバック。3〜4.5m：1歩近づいて叩く（点火を止める）。4.5m以上：8m未満でも弓で撃つ（弓の下限は約4m）。
  - 起爆中または追い詰められた同一個体が4.5m以内なら、汎用の約2秒の近接待ちは行わない。既知の安全な候補へ最大1.5mの反撃ステップを試し、候補拒否後も次の判定で個体・脅威・経路を読み直す。新しい個体へ状態を引き継がず、射程や移動成功だけで命中を確定しない。
  - 回避できなかった直後は待たずに再判定する。
  - 通常敵用の接近待ちは使わない。短い接近の再計画には回数と時間の上限を設け、同じ対象への実近接プレビューが成立した時点で攻撃を再判断する。成立しなければ `CREEPER_APPROACH_BLOCKED` として既存の退避へ移る。追い詰められた記録は接続・生存回・個体IDに結び付ける。
- 歩いて近づけないクリーパーも、撃つ対象にする（接近しないので経路は不要）。
- 点火（`primed`）の検知はログに記録する。

## 5. HPが低いとき（ユーザー確認済み・現行仕様のまま）

HP割合 = 現在HP ÷ 最大HP（通常20）。

| 状態 | 動き |
|---|---|
| 40%未満（`HP_RETREAT`）になったら「撤退状態」 | 新しい交戦は、4m以内の相手への反撃だけ |
| 撤退状態で、直近5秒以内に被弾している | 反撃範囲を広げる（弓があれば32m、なければ12m）。逃げても撃たれ続けるため |
| 撤退状態で敵1体 | 後退せず、剣の連打で押し切る |
| 撤退状態で6m以内に敵2体以上、かつ3m以内に敵がいない | 離脱する（`HP_DISENGAGE`）。待機保護の退避と回復に任せる |
| 撤退状態で6m以内に敵2体以上、かつ3m以内に敵がいる | 逃げずに戦う（同じ速さのゾンビからは逃げ切れないため） |
| 60%以上（`HP_RESUME`）に回復 | 撤退状態を解除し、通常の交戦に戻る |

- **間合いの取り直し（1発ごとに後退）** は、HPが40%以上で6m以内に敵が2体以上いるとき、`melee_kite` 分類の敵（ゾンビ・クモ等）に対してだけ行う。
- 被弾から2秒以内は「押されている」と判定する（剣のジャンプ斬りをしない理由の一つ）。

## 6. 防具（`src/armor.js`）
- 持ち物の防具を部位（頭・胴・脚・足）ごとに比較し、防御力の高いものを着る。同じならタフネスの高いもの。
  - 例：ネザライト ＞ ダイヤ ＞ 鉄 ＞ 鎖 ＞ 金 ＞ 革。
- 着るタイミング：
  - 戦闘外：8m以内に敵がいないとき、3秒ごとに確認
  - 戦闘開始時：最寄りの敵が6mより遠いとき、最大1.5秒
- サーバーが要求を受理してから「装備完了」とする。外した防具は持ち物に戻る。
- サーバーに拒否されたら、着ている状態を「不明」に戻し、サーバーが防具欄を送り直すまで装備を試みない（再接続直後の誤認対策）。
- コードの再読み込みでは、着ている状態を保持する（再読み込み時に流し直すワールド開始の通信は無視する）。

## 7. 食事・持ち物との両立
- 戦闘候補に選ばれた敵がいれば、距離6mを超えていても食事を直ちに中断して戦闘へ移る。食事の使用解除と入力停止は元の食事が所有する入力に対して1回だけ行い、遅れた終了処理で新しい武器や戦闘入力を解除しない。
- 近くに敵がいない被ダメージ（餓死、流れ矢）では食事を止めない。止めると、食べられずに死ぬまで繰り返していた。
- 食事の中断や、矢の発射が確認できなかった場合は、その品目の数だけが不確かになる。持ち物全体を「不明」にはしない（全体が不明になると、すべての攻撃が止まるため）。
- 持ち物全体が本当に不明になったときは、0.5秒後から、6秒以上の間隔でサーバーに再同期を要求する（1回の生存につき3回まで）。

---

## 8. 待機保護（逃げ処理）との関係
- 戦闘をしていないあいだは、待機保護（`待機保護の退避`）が危険な敵から離れる。
- 戦闘を開始すると、待機保護の退避は止まり、戦闘が優先される。
- **はまり対策**：逃げ処理が「経路なし／動けず」で3回続き、その間被弾がなければ、逃げ処理を **20秒止める**（`ESCAPE_PAUSE_MS`）。被弾するか、4m以内に敵が来たらすぐ再開する。止めているあいだは、通常の移動や戦闘で抜け出す。

## 9. ログ（ライブログ http://127.0.0.1:3001/logs の「戦闘」で絞り込み可）

| ログ | 意味 |
|---|---|
| `戦闘接近` | 接近（理由の判定コード付き） |
| `戦闘スライス` | 剣・弓の1回の実行結果（攻撃回数・射数） |
| `戦闘終了` | 終了の理由コード・所要時間 |
| `剣で攻撃` | 攻撃要求の送信（前回からの間隔ms）。命中は未確認 |
| `矢を発射` | 発射要求（距離・引き絞り時間）。矢の実出現と消費は別途照合 |
| `射撃後の標的ダメージ` | 射撃後に標的の被ダメージ通知を受信。攻撃者・命中の帰属は未確認 |
| `矢の誤差` | 矢の通過位置の誤差（上下・左右）。発射時の対象IDを保持し、`by=lost` だけでは命中としない |
| `引き絞りを保ったまま標的を切替` | 引き絞り中に標的が倒れ、別の敵へ照準を移した |
| `射線の通る位置へ移動` / `射線確保の候補なし` | 射線を作る移動 |
| `クリーパー後退開始/終了`, `クリーパー回避` | クリーパーの回避 |
| `間合いの取り直し` | 1発ごとの後退 |
| `防具を装備` | 防具の装備結果 |
| `待機保護の退避を一時停止` | はまり対策の発動 |

診断API（`POST /action`, `group: diagnostics`）：
- `combatCandidates`：各敵が候補になる・ならない理由
- `acquireDenials`：戦闘開始が拒否された理由
- `threatReachability`：経路の判定
- `armor`：防具の状態
- `userTick`：判断周期の稼働状況
- `sightFrom(x,y,z)`：指定地点から各敵への射線
- `blocksAround`：足元周辺のブロック

戦闘の開始・状態・終了・中断と攻撃要求には、個体ID、接続、次元、生存回の `context` を付けます。標的IDは被弾の加害者を示す証拠には使いません。

## 10. 主な終了・中断コード

| コード | 意味 |
|---|---|
| `TARGET_DEAD` | サーバーが標的の死亡を通知（撃破） |
| `TARGET_REMOVED` / `TARGET_UNKNOWN` | 標的が消えた・見えなくなった（撃破は未確認） |
| `APPROACH_NOT_READY` | 接近する足場・経路がない |
| `CREEPER_APPROACH_BLOCKED` | クリーパーへの短い接近が成立せず、通常敵用の待機を避けて退避を評価した |
| `LOS_BLOCKED` | 弓の射線がない |
| `CREEPER_NO_SIGHT` | クリーパーから8m以上離れた位置で、射線の通る場所がない |
| `CREEPER_CLOSING` / `CREEPER_EVADED` | クリーパーが迫っているので後退した／回避が完了した |
| `HP_RETREAT` / `HP_DISENGAGE` | HPが低いため戦わない／離脱 |
| `SHOT_UNCONFIRMED` | 矢が出たことを確認できない（2回続くと中断） |
| `DRAW_REJECTED` | サーバーが引き絞りを拒否（撃ち直す） |
| `CHASE_LIMIT` | 戦闘開始地点から40m以上離れた |
| `ACQUIRE_DENIED` | 作業側から制御権を取れなかった（武器なしで逃走中など） |

---

## 11. 既知の制限
- 敵が10体を超える夜の起伏地形では、まだ死ぬことがある（4回中3回は死亡、1回は3分生存して15体撃破）。
- 射線が通らない敵を追って作業を止めない。認識・攻撃アクセスは受信観測と既知地形による判定で、サーバー内部のAI標的そのものではない。
- 弓は1回の戦闘で1体を狙う。囲まれる前に数を減らす立ち回り（距離を取りながら連射する等）は限定的。
- 防具を持っていなければ装備しない（クラフトや入手はしない）。
