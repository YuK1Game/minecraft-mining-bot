# 2026-11-09：補給作業地点の地形判定と停止原因の診断

## 対象と確認できた範囲

報告は、現在地 `(-4,65,16)` から候補26件を調べても `STORAGE_SITE_UNOBSERVED` となった補給処理、その後に新規計画で発生した `FLUID_OR_EXTRA_LAYER`、待機保護の `bodyClear=false` です。

実Realmの地形と完全な受信記録にはアクセスしていません。この変更は、模擬地形で再現した設置判定の不一致を直すもので、利用者の26件すべての原因を確定したものではありません。液体の帰還先と身体の衝突判定を無効化して動かす変更ではありません。

## 補給場所の修正

- 歩行プランナーは草のある立ち位置を許可するのに、携帯箱側は空気しか許可しない不一致を修正。乾いた衝突のない短い草・花など、明示リストの植物は立ち位置として扱えます。
- 粘土・ポドゾル・砂岩など、既知の安全なフルブロック床も使用します。砂・砂利は、その下を最大8マスまで読み、全段受信済みで安定した床に支えられている場合だけ使用します。浮いた砂、未知の床、危険物、半端な高さの床は拒否します。
- シュルカーの設置は従来の2マス先を優先し、使えない場合は届く1マス先も候補にします。本人・他エンティティとの重なり、設置許可、周辺、視線は再確認します。
- 箱の場所や視線に植物がある場合、最大4ブロックの除去計画を提案します。対象は既存の採掘許可範囲内の乾いた明示リストの植物のみです。作物・葉・水草・水没した植物・保護物・自分の足元は対象外です。
- 採掘場所へ実際に移動した後、近い植物から通常の採掘で除去し、その座標の空気の受信を確認します。実際の空間を再検査してから補給箱を設置します。計画だけで地形を空気に変えたり、コマンドで消したりしません。
- 所持品容量、実際の採掘対象名とruntime ID、位置、接続・生存回、戦闘・手動停止、保存を引き続き確認します。補給中の既存子チェックポイントは移動や除去で捨てません。

処理順は **移動 → 必要な植物だけ通常採掘 → 空気の受信 → 設置可能性の再確認 → 補給・箱回収** です。補給不要なら追加作業はしません。

## 停止診断

- `supply_site_blocked`: `cause`・`position`・`block`・理由別件数を表示します。未受信、床不適、置けない空間、他エンティティ、許可外、視線不適などを区別します。
- `supply_site_prepare`: 実行する植物除去の座標とブロック名です。これ自体は成功ログではありません。受信した空気と保存が必要です。
- 帰還計画: `pauseDetails` の先頭に代表座標のブロック名・追加レイヤーと候補全体の理由別件数を含めます。1候補に水があったという情報を、全候補が水だという意味にはしません。
- `待機保護の体勢詳細`: `BODY_COLLISION`、`BODY_IN_WATER`、`BODY_IN_LAVA`、`BODY_TERRAIN_UNCONFIRMED` などを座標付きで記録します。従来の身体寸法・接触誤差・危険物判定・戦闘方針は維持します。不正な形状も未確認として拒否します。

安全な地上帰還先が本当にない場合や、身体が液体・衝突・未受信の空間にある場合は停止が残ります。初期セットを繰り返し配布して直る問題ではありません。
