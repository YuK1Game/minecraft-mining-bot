# プレイヤーモードの帰還（拠点へ戻って収納する）

プレイヤーモードで「作業中に帰還を決め、拠点へ移動し、収納を受信で確認してから、作業を計画し直して再開する」処理の設計と確認方法です。コードは `src/modes/return/`、決める条件と預ける物は `src/modes/player-base.js` にあります。

## 考え方

- **目的と操作を分ける**。目的（拠点へ戻って預ける）は、座標の途中経過・Promise・タイマーを持たない小さなデータで、失敗・戦闘・食事・夜・行動コードの反映・再起動をまたいで残る。操作（歩く・登る・開ける・入れる）は残さず、中断のあとは、その時に受信している状態から計画し直す。古い操作を送り直さない。
- **成功は受信で決める**。移動は受信した位置、チェストは受信したブロックとスロット、収納は受信した持ち物の枠の減少で確定する。0個の収納は成功ではない。
- **未確認を、空・満杯・安全と見なさない**。開けられなかったチェスト、中身が届かなかったチェストは「不明」で、「満杯」ではない。
- **同じ失敗を、何も変わらないまま繰り返さない**。失敗は、段階・対象・原因のコード・それが依存する状態（立っている場所など）ごとに数え、3回目で別の方法へ移るか、目的を保留する。回数と時間には上限がある。

## 段階と終了条件

| 段階 | 終了条件（受信で確認） | 戻り先 |
| --- | --- | --- |
| 状態の確認 | 位置・持ち物と、足元のブロックを受信している。預ける物も取り出す物もなければ、ここで完了 | — |
| 出発位置の確保 | 頭上に地面がなく、水の中でない | — |
| 拠点へ移動 | 拠点から水平20m以内 | 屋根の下・水の中に戻ったら「出発位置の確保」へ |
| チェストへ接近 | 開く操作を送れる場所に立っている（クリックする面まで4.5m以内で、そこまでの視線が受信した空きのマスだけを通る。開く操作と同じ判定） | 20mより遠ければ「拠点へ移動」へ |
| チェストの確認 | 開いて全スロットを受信し、空きがある | 今の場所から開けないチェストは「チェストへ接近」へ。満杯（受信した空き0）なら次のチェスト、なければ新しいチェスト |
| 収納 | 預ける物が受信した持ち物からなくなった | 満杯になったら「チェストの確認」へ |
| 収納の確認 | 預ける物が残っていない。必要なら取り出しも済んだ | 残っていれば「収納」へ。取り出したい物があるかもしれないチェスト（中身を受信して持っていると分かった、またはまだ開けていない）が今の場所から開けられない時は、そのチェストへ「チェストへ接近」（1つにつき1回） |
| 作業の再開 | 操作を手放し、作業を目標（objective）から計画し直す | — |

「着いた」（20m以内）と「チェストを開けられる場所に立った」は別の段階です。家の中の拠点へは、ドアを開け、チェストの横の立てるマスへ歩きます。横のマスは、そこから開けられると分かるもの（開く操作と同じ判定）を先に、6か所まで試します。家の中からどのマスへも行けない時は、ドアから外へ出て、もう一度試します（家の外の壁ぎわのチェスト）。新しく置いたチェストも、近くで見つけたチェストも、開ける前に同じ接近をします。

候補になるチェストは、拠点のチェスト、家の2つ目のラージチェスト、いま使っているチェスト、Bot の5マス以内に立っているチェストです。預ける順番は、ダイヤ、ほかの貴重品、それ以外です（途中でチェストが満杯になった時に、外に残るのが石材になるように）。家の中から出発する時は、ドアから外へ出てから長距離移動を始めます。水の中からは、岸へ上がったことを受信した位置で確かめてから長距離移動を始めます。上がれなかった時は長距離移動を始めません。

## 操作権

- 入口は1つ（2秒ごとの `tick`）。目的がある間、2つ目の目的は作らない。
- 自律作業に停止を頼み、**終わったことを確認してから**最初の操作を始める。8秒待っても確認できなければ `STOP_UNCONFIRMED` とし、何も始めない。
- 優先するもの（敵から離れる・射線から外れる・避難・戦闘・食事・ほかの立て直し作業）が動いている間は、進行中の段階を次の確認点で終え、何も始めずに待つ。待った時間と中断は、失敗にも予算にも数えない。終わったら、今の状態から計画し直す。
- 同じ持ち主が5分たっても操作を手放さない時は、待ち続けずに目的を保留する（`OWNER_NOT_RELEASED`）。保留では何も始めず、自律作業も始めない（操作はその持ち主のもの）。保留の間は「帰還が動いている」と数えないので、ほかの作業を待たせない。持ち主がいなくなった時か、遅くとも10分後に見直す。
- 目的の完了・保留・断念のあとにだけ、自律作業を再開する。途中の失敗では再開しない。
- 手動の停止（プレイ停止・`/stop`）とモード切替は目的を取り消し、何も再開しない。取り消したあとに終わった古い段階の結果は使わない（世代の番号で見分ける）。
- 接続・次元・生存回が変わったら、それまでに観測したもの（チェストの空き・失敗の記憶）を捨て、状態の確認からやり直す。死亡で預ける物がなくなっていれば、そこで完了する。

## 結果とコード

段階とチェストの操作は、同じ形の結果を返します。判断は `status` と `code` だけで行い、日本語の文（`detail`）はログ用です。

| status | 意味 |
| --- | --- |
| completed | 終了条件を受信で確認した |
| partial | 一部は受信で確認できた。残りがある |
| blocked | 前提が足りない。`retry` に、何が変われば再試行できるかを入れる |
| failed | この方法では進めない |
| interrupted | 優先するものに操作を渡した |
| cancelled | 停止・モード切替 |

`retry.kind`: `now`・`owner_released`（前の操作が終わった）・`inventory_update`（持ち物を受信し直した）・`container_update`（チェストの中身を受信した）・`terrain_received`・`position_changed`（別の場所に立った）・`supplies_changed`（木・チェストを持った）・`time`（通信と、自分で動くものだけ）。

主なコード:

| 段階 | コード | 扱い |
| --- | --- | --- |
| 操作権 | `STOP_UNCONFIRMED` | 30秒まで待って再確認。3回で保留 |
| 操作権 | `OWNER_NOT_RELEASED` | 優先するものが5分たっても終わらない。何も始めずに保留し、持ち主がいなくなったら見直す |
| 出発位置 | `CLIMB_FAILED`・`WATER_EXIT_FAILED` | 同じ場所で3回まで。水からは長距離移動を始めない |
| 移動 | `TRAVEL_SHORT`（8m以上近づいた） | 進捗あり。今の場所から続ける |
| 移動 | `TRAVEL_NO_PROGRESS`（4分間8m近づかない） | 同じ場所から3回で回り道（左右48m、2回まで）。その後は保留 |
| 接近 | `CHEST_UNREACHED` | 開けられる場所に立てなかった。満杯とは扱わない。3回で、チェストから離れている時は別の側から近づく（長距離移動でチェストの30m先へ回り、そこから入り直す。ドアのある側、次に今いる側の反対。2回まで）。それでもだめならほかのチェスト。届かないチェストしかない時は新しいチェストを置かずに保留する。受信で満杯と確かめたチェストがある拠点では、新しいチェストを置ける |
| 確認・収納 | `CONTAINER_NOT_IN_REACH`・`CONTAINER_NOT_VISIBLE` | 今の場所からは届かない・見えない。開く操作を送らず、「チェストへ接近」へ戻る |
| 確認・収納 | `CONTAINER_OPEN_REFUSED` | 開かなかった。満杯とは扱わない。3回でほかのチェストか新しいチェスト |
| 確認・収納 | `CONTAINER_CONTENTS_UNKNOWN` | 開いたが全スロットが届かない。満杯とは扱わない。何も入れない |
| 確認・収納 | `CONTAINER_FULL` | 受信した空きが0。ラージチェストの2つは1つの容器として扱い、もう片方を開け直さない |
| 収納 | `TRANSFER_UNCONFIRMED` | 送った移動の結果が未確認。持ち物を受信し直すまで何も送らない |
| 収納 | `TRANSFER_REJECTED` | サーバーが断った。3回で保留 |
| 収納 | `CONTROLS_HELD`・`DEPOSIT_INTERRUPTED` | 戦闘などに渡した。済んだ分は数え、残りはあとで入れる |
| 確認 | `CARGO_REMAINS` | 預ける物が残っている。収納へ戻る |
| 確認 | `RESTOCK_UNCONFIRMED` | 取り出したい物が残っていて、試せるチェストが残っていない。すぐ保留する |
| 確認 | 開かなかった・何も出なかったチェストのコード（`CONTAINER_OPEN_REFUSED`・`CONTAINER_CONTENTS_UNKNOWN`・`INVENTORY_UNKNOWN`・`WITHDRAW_REFUSED` など） | チェスト自身の答えをそのまま返す（再試行の条件も）。3回で保留 |
| 状態 | `BASE_IN_OTHER_DIMENSION` | すぐ保留。次元が変わったら再開 |
| 状態・接近・確認 | `TERRAIN_UNKNOWN` | 足元かチェストのブロックが未受信。受信するまで何も決めない（再接続の直後） |
| 材料 | `NO_CHEST_MATERIAL` | チェストを作れない。木・チェストを持ったら再開 |

収納した数は、受信した持ち物の枠が減った分だけを、1回だけ数えます。応答が届かなかった移動は数えず、受信し直した持ち物から残りを決めるので、同じ山を2回送りません（その分、収納済みの数は実際より少なく出ることがあります）。

## 回数・時間の上限と根拠

| 定数 | 値 | 根拠 |
| --- | --- | --- |
| 同じ失敗 | 3回 | この Bot のほかの再試行と同じ回数 |
| 1つの目的の失敗 | 12回（再評価ごとに＋4） | 違う問題が4つ、それぞれ3回まで |
| 実行時間 | 30分（再評価ごとに＋10分） | 長距離移動の上限20分＋登りと収納。中断中の時間は数えない |
| 長距離移動1回 | 距離1mにつき2秒（5〜20分）。4分間8m近づかなければ終える | 実Realm 2026-11-17 20:36〜21:02 JST の記録（進んでいる移動を5分で切らない） |
| 回り道 | 2回（左右48m） | 危険地帯・水場を1つ避ける大きさ |
| 別の側からの接近 | 2回（チェストの30m先） | 着いた（20m以内）のに近づけない側（家の上の丘など）から、長距離移動の「着いた」が家の反対側になる距離 |
| 失敗した段階のやり直し | 2秒あける | 3回の試行が一瞬で終わらないように（実Realm 2026-11-18 03:28 JST: 20ミリ秒で3回） |
| 続けての中断 | 10回で失敗1回に数える | 持ち主のいない中断が続く場合の上限。優先するもの（敵から離れる・戦闘など）が持っている中断は、何回続いても数えない（実Realm 2026-11-18 04:18〜04:22 JST: 11回続いた「敵から離れる」が失敗1回に数えられた） |
| 停止の確認 | 8秒 | 自律作業の1つの操作が終わるまでの長さ |
| 持ち主を待つ時間 | 5分で保留 | 戦闘・食事・退避・1回の立て直し作業はふつう数分で終わる。終わらない持ち主のために、目的が画面に出たまま進まない状態を続けない（実Realm 2026-11-18 05:49〜06:07 JST: 終わらない立て直しを18分待った） |
| 近くの敵による開始の待ち | 60秒 | 戦闘にならず立っているだけの敵のために始めない状態を続けない（実Realm 2026-11-18 02:47 JST: 9m先・6段上のスケルトンで、35/36枠・ダイヤ17個のまま帰還が始まらなかった）。戦闘・退避が始まれば、いつでも中断する |
| 保留 | 再開の条件が変わるまで。遅くとも10分 | 敵・危険地帯は自分で動くので、時間でも1回見直す |
| 再評価 | 6回で断念。次の目的は10分後 | 合計の試行は 12＋4×6＝36回が上限 |
| 失敗の記憶 | 30分。接続・次元・生存回ごと | 古い失敗で新しい状況を断り続けない |

保留中は操作を手放し、自律作業を続けます（ほかの作業も止めません）。保留から再開するのは、原因に応じた変化があった時です: チェストの材料の数が変わった、接続・次元・生存回が変わった、または10分たった。場所の変化（水平32m以上）で再開するのは、どこかへ行く段階（出発位置の確保・拠点へ移動・チェストへ接近）の失敗と、チェストを置けなかった時だけです。上下8段以上の変化で再開するのは、出発位置の確保（坑道から出る）の失敗だけです。チェストが満杯・開かない・材料がない、という保留は、Bot がどこへ動いても再開しません（実Realm 2026-11-18 03:17〜03:20 JST: チェストのための保留が、拠点の下の採掘で20秒おきに再開され、3分で断念した）。失敗の記憶は目的とは別に残るので、断念のあとに同じ拠点への新しい目的ができても、同じ場所の同じ失敗は3回からやり直しになりません。別々の失敗が輪になる場合（A→B→A→B、A→B→C→A→B→C）も、同じ失敗3回と同じ扱いにします。

## 残る場所

- 目的: `shared.playerReturn`（行動コードの反映をまたぐ）と `.local/player-return.json`（再起動をまたぐ）。復元した目的は段階を「状態の確認」に戻す。保存に失敗した時は1回だけログに出し、目的は続ける（再起動では引き継げない）。
- 失敗の記憶: `shared.playerReturnFailures` と同じファイル。
- プレイ中でない時（`shared.playerWanted` が true でない）に復元した目的は取り消し、何も始めない。

## 画面とログ

- 「今していること」欄: `拠点へ資材を預けに行きます（<段階>）。` 中断中は `…のため待機` を添える。保留中は帰還の表示を出さない（自律作業の表示になる）。
- ログ: 段階の移り変わり、失敗（コード・同じ条件での回数・全体の回数・再試行の条件）、中断と再開、保留と再評価、完了・断念・取り消し。
- `operations.mode` の拠点の状態（`base.status().goal`）に、目的のID・段階・収納済み・残り・試行回数・最後の失敗・保留の理由・保存できているかを出す。

## 確認のしかた

`npm run test:player`（`scripts/player-tests.js`）がプレイヤーモードの専用レーンです。全テストが実行されて合格した時だけ成功し、失敗・時間切れ・取り消し・スキップ・未実行が1件でもあれば失敗します。CI（`.github/workflows/ci.yml`）でも実行します。

受け入れシナリオは `test/player-return.test.js` にあります。`test/helpers/player-return-sim.js` の小さな Realm の上で、実際のモジュール（`player-base.js`、`return/*`、`player-storage-ports.js`、`player-scaffold-ports.js`、`player-water.js`、`house-door.js`、`house-exit.js`、`actions/chest.js` と 1.26.60 のパケット）を動かします。模擬しているのは、サーバー（持ち物とチェストの中身を持ち、パケットに答える）、歩行（時間がかかり、閉じたドアで止まる）、長距離移動、登り、自律作業の停止の遅れ、戦闘です。どの移動も模擬の時間がかかり、途中で切れます。呼んだだけで着くことはありません。

| シナリオ | 内容 |
| --- | --- |
| S1 | 通常の帰還: 長距離移動2区間、最後の接近、受信による収納、作業の再計画 |
| S2 | 途中の戦闘と食事: 目的を保って待ち、今の場所から続ける |
| S3 | 停止の確認を待つ。確認できない時は何も始めず保留し、確認できたら続ける |
| S4 | 水の中から: 岸へ上がってから出発。上がれない時は長距離移動を始めない |
| S5 | 家のドアを開けてからチェストへ。家の中からは外へ出てから出発。坂の上の拠点 |
| S6 | 満杯（受信で確認）・中身が不明・ラージチェストの片割れ・歩いて行けないチェストの区別 |
| S7 | 応答のない移動、応答だけ届かない移動、断られた移動、収納の途中の戦闘。二重に送らない・数えない |
| S8 | 途中の死亡、収納の途中の再接続、別の次元 |
| S9 | 行動コードの反映と再起動をまたぐ。保存の失敗。プレイ中でない時の復元 |
| S10 | 手動の停止とモード切替。古い段階の完了は何も変えない |
| S11 | 同じ失敗は3回で保留し、場所が変わったら再開する |
| S12 | 近づけない移動: 回り道、保留、再評価、断念。その間も作業は止まらない |
| S13 | 近くに立つだけの敵で始まらない状態を続けない。高さ1のすき間は立つ場所に選ばない |
| S14 | 収納チェスト（`player-storage.js`）の従来の呼び方と、露天掘りモードとの境界 |

## 実Realmでの確認
