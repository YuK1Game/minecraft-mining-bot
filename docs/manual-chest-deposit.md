# ラージチェストへの手動全収納

管理画面の所持品欄にある「ラージチェストへ全収納」は、本番環境向けの通常収納操作です。デバッグ初期化とは別の機能で、主所持品36枠・防具4枠・オフハンドを移します。シュルカーは開かず、そのまま収納します。

Botから届く範囲のチェストを近い順に最大8個開き、実際に受信した54枠がすべて空のラージチェストを選びます。探索範囲は水平4ブロック・上下2ブロック、操作距離は目線から4.5m以内です。移動・設置・採掘・アイテム生成・消去・管理者コマンドは行いません。

1. 採掘や持ち替えなどの操作を終了させ、空のラージチェストの近くでボタンを押します。
2. 収納先と対象数を確認し、120秒以内に「すべて収納」を押します。
3. 収納中は進行数を表示し、「中断」で停止できます。途中の操作は同じ収納先・記録から再確認して再開します。

確認後に所持品・ジョブ・接続先・生存回・コード世代が変わった場合は開始しません。開始直前にも新しく54枠を受信し、最初の転送要求の直前まで空であることを照合します。移動は通常のitem-stack requestで行い、受理応答と両側の実データを照合します。コマンド受付や予測だけで成功扱いにしません。

戦闘は収納の終了を待たずに操作権を取り、これから送る収納要求を止めます。送信済み要求の受信監視は残し、未確定の転送をチェックポイントへ保持します。自動防具装備・他の手動操作・ホットリロードは収納と競合しないよう制限します。収納だけで採掘や自律作業を再開しません。

移動記録は `.local/manual-chest-deposit/<operationId>.json` と `latest.json` に保存します。再読込後も未完了記録を検出します。接続や生存回が変わった記録は、自動で新しい操作へ置き換えず停止します。その場合はチェストと持ち物の実状態を確認する必要があります。

APIは固定の `storagePreview`・`storageStart`・`storageCancel` に限定し、開始は一度限りの確認トークンを必要とします。内部のNBTやチェックポイントは画面へ返しません。管理画面とBotホストの専用経路の追加は再起動が必要です。更新前のサーバーではボタンを無効にします。

デバッグチェスト設置は別の処理です。こちらは確認後にBotの所持品・防具・オフハンドを空にしてからキット入りの地上ラージチェストを構築します。新しい確認文字列を必要とし、古い画面から拡張後の処理は実行できません。
