# 2026-11-09：補給前に採掘エリアへ移動

## 修正した順序

開始直後の不足判定と、補給箱の設置を分離しました。

1. 補給が必要な場合、採掘対象の水平範囲内から、通常の経路で歩いて行ける立ち位置とシュルカー設置空間を探します。
2. 移動先を保存し、通常の移動コントローラーで移動します。
3. 足元座標・足場・設置空間を再評価してから `RESTOCK` に入り、既存の設置→補給→回収→内容照合を行います。
4. 補給が不要なら移動・開封を追加しません。既に作業可能な採掘層にいればその場を使用し、毎回地上へ戻りません。

`PREFLIGHT → RESTOCK` と進み、採掘範囲から離れた現在地の周辺だけで設置場所を探していた経路を修正しています。現行標準セットの土192個に対し、補給判定は帰還用192個＋止水用32個を要求するため、最初の補給自体は正常です。所持数や補給基準を変更して回避してはいません。

## 設置と移動の境界

- 作業候補は受信済みの足場、空間、設置面の視線、エンティティ重なりを、実設置と同じプランナーで確認します。プレビューは予測で、現在位置や地形を上書きしません。
- 経路は既存のtravel領域と段差制約に従い、ネイティブ移動の開始可能性も確認します。未知の地形・通れない壁や穴を飛び越えたり、移動権限を拡張したりしません。
- 未採掘の地表に箱を置くため、対象チャンク内の `yTop + 1` までを一時補給に限って認めます。保護領域、帰還予約、体の通行範囲は維持し、通常の採掘・設置権限は変更しません。
- 候補評価は最大1024立ち位置、ネイティブ経路のプレビューは最大8回です。上限到達を未受信地形や成功とは扱いません。
- 移動中の手動停止・戦闘・死亡・接続先変更、移動失敗、到着時の地形変更、保存失敗で箱を設置しません。移動と補給物の受け取りを同一の成功証拠にしません。

## 既存ジョブ

今回の `SUPPLY_RESTOCK_BLOCKED / STORAGE_SITE_UNOBSERVED` で停止し、まだ設置子処理がない場合は、同じoperationIdと補給記録を保持したまま、再開時に移動先を再計画します。

すでに設置・収納・回収の子チェックポイントがある場合は、新しい場所へ勝手に移動しません。元の箱と未確定操作の照合が優先です。既存の箱を削除せず、取引をなかったことにしたり操作IDを取り直したりしません。

## ログと反映

移動が必要な場合は `supply_approach`、到着後は `supply_arrived` を記録します。移動できない場合は `SUPPLY_APPROACH_UNREACHABLE`、移動に失敗した場合は `SUPPLY_APPROACH_MOVE_FAILED` などを停止詳細の先頭に出します。実際に設置空間がない場合の `STORAGE_SITE_UNOBSERVED` は残ります。

main取込後は `git pull --ff-only origin main`、行動コード反映ログを確認して「再開」。この修正はruntimeと行動モジュールのみで、Botの切断、管理画面の再起動、初期セットの再配布、新規ジョブの作成は不要です。

## 検証の範囲

`test/review-supply-approach.test.js` は、負座標の範囲外からの開始、既存停止ジョブの再開、地表上、採掘途中の同じ層、補給不要、移動拒否・未到着・地形変更、戦闘・死亡・手動停止・ワールド変更、保存失敗、設置済み箱の引継ぎを検証します。実portable storageの設置・補給・回収を組み合わせたテストも含みます。

テストの地形・移動・受信・サーバー応答は模擬です。実Realm接続・実際の採掘／補給・利用者PCの操作は未実施です。全件テストには以前からの失敗があり、関連テスト成功と全件成功は区別します。
