# プレイヤーモードのブランチマイニング

鉱石への最短経路をその都度掘る方式を、保存した採掘場に通う方式へ切り替える。対象は現世の鉄・石炭・ダイヤ・金・レッドストーン。通常の木材・食料・砂などの調達と、露天掘りモードの範囲・収納方式は別に扱う。

## 採掘範囲と2層

`src/modes/mining/mine-survey.js` が、現在のサーバー接続で受信した World のブロックを読む。画面の鉱石一覧の件数上限や、未受信の地形を空気として扱う推測は使わない。受信中の範囲変更・接続・次元・生存回の変化は計算を中断する。地形の読み取りと候補の評価は区切って実行し、戦闘・停止処理へ実行権を渡す。

`mine-plan.js` は入口の位置、坑道の向き、矩形の大きさ、上下の高さを有限の候補から比較する。矩形の辺は16・24・32ブロックから選ぶ。上層は鉄・石炭、下層はダイヤを中心とする。上層の高さ候補は Y16・32・48。下層は受信した鉱石の高さから選び、特定のYを常に最適とは扱わない。縦坑の深さは191ブロック以内とし、下層の半段の床から地上まで、はしご移動の192ブロック上限内で帰還できる計画に限る。

比較するのは、その計画の幹線・支線と制限付きの鉱脈回収で届く鉱石だけ。矩形の中のすべての鉱石を収穫できると数えない。同じ鉱石や同じ施工セルの重複を除き、必要数量を得るまでの掘削、縦坑、床の交換、照明、収納箱、運搬を評価する。結果の最適性は「現在の受信地形と探索予算内の比較」の範囲に限られる。未受信の遠方を含むワールド全体の最適地は分からない。

## 施工

| 部分 | 仕様 |
| --- | --- |
| 縦坑 | 2×2の施工用空間を1段ずつ下りる。固い作業足場から隣の列を掘り、支持壁とはしごを確認してから降下する。非はしご列は踊り場を残して埋め戻す |
| 幹線 | 幅2、高さ3の規則的な通路 |
| 支線 | 幅1、高さ2以上。3ブロック間隔で、支線間に2ブロックを残す |
| 床 | 下付きの丸石ハーフブロック。床ブロックの上端は半段で、その上に2ブロック以上の空間を確保する |
| 鉱脈 | 通路に水平につながる高さ2の小さな空間だけを半径3・最大32掘削ブロックの範囲で追い、追加した穴を埋め戻す。床下や屋根上を任意に掘り抜かない |
| 洞窟 | 通路の横や天井への開口を塞ぐ。未受信の空洞へ進まない |

自分を支える床を掘る操作は許可しない。床のハーフブロック化は隣の確認済み足場から行い、置き換えるハーフブロックの所持を先に確認する。下付きの状態・支持範囲・足元の半段の高さを確認した場合だけ、完成した床から通常採掘を続けられる。鉱脈の追加掘削も、その時点で開いた穴をすべて埋め戻せる丸石を確保してから始める。

はしごは専用の `actions/ladder.js` と Runtime の既存入力ストリームを使う。入力の送信や予測位置だけでは到着とせず、実際の位置証明まで待つ。乗降先には支持された足場が必要。戦闘へ操作権が移った場合は、新しい所有者の入力を止めずに自分の処理を中断する。

## 湧き潰し

通常の松明と下付きハーフブロックを施工工程に含める。採掘の終了後にバックグラウンド処理へ任せる方式ではない。

受信した通常の松明から、受信済みの開いたマスだけを通る明るさの下限を計算する。目標は8以上。壁・未受信セルを光が透過すると数えず、溶岩、稼働中のかまど、魂の松明をこの証明へ流用しない。これは受信ブロックと既知の発光値からの保守的な計算で、サーバーから照度の数値を直接取得したという意味ではない。

通路の松明は最大6ブロック間隔。広い収納室は両壁に4ブロック間隔で置く。床、頭上の空間、開口の封鎖、照明の確認が揃うまで次の区間へ進まない。すでに存在する敵への対処は従来の戦闘・退避処理を継続する。

## 複数ラージチェストと補給

各層に収納室を設ける。予定する掘削物と鉱石のドロップをスタック数へ換算し、ラージチェスト1個あたり43枠を計画容量とする。54枠のうち11枠を種類の増加やスタックの偏りのために残し、必要な貨物用の個数と補給用1個を配置する。

2つのチェストの設置場所を先に保存し、各設置の受信を確認する。隣接しているだけではラージチェストと判定しない。実際に開いて54枠を受信し、向きと組の対応を確認してから使う。27枠や未受信を成功扱いしない。複数の組は1ブロック以上離し、予定外の組み合わせを防ぐ。

所持品が埋まる前に鉱石・石材を収納する。要求中の資材と修繕用ブロックは手元に残す。満杯なら掘削を止め、石材を捨てる旧処理へ戻さない。取り出し・預け入れは既存の容器受信処理を使い、記憶した内容だけで成功を判定しない。

はしご、床材、松明、チェストは施工前に用意する。最初から下層の依頼が来ても、上層までの未施工分を含めてはしごを準備する。松明の準備で石炭採掘を再帰的に開始しないよう、必要なら木炭を作る。補給は低下した残量に応じてまとめて行う。材料の種類が混ざっている場合のクラフト数は、受信したレシピと所持品のプレビューで実行可能な数へ調整する。

地下で足りなくなった木材などを探し回らず、施工済み通路とはしごで地上へ戻る。作業台・かまどを予定された坑道へ勝手に置かない。ツルハシは実際の採掘と同じ `digTool` で選び、耐久度が不明・残り2以下の道具だけなら補充する。地上の既存設備も開ける視線と立ち位置を確認し、使えないかまどのために所持設備を置けないまま繰り返さない。

## 保存・再開と達成判定

計画、層ごとの区間カーソル、施工中の操作、鉱脈の埋戻し、収納の登録を、既存のドラゴン遠征のチェックポイントに保存する。大量のブロック配列ではなく線と短い進捗を持ち、既存の1MB制限を維持する。

ワールドに属する計画と、接続・生存回に属する操作の確認を分ける。操作前の予定を保存し、受信した成果を確認してから進捗を保存する。未確認の設置を同じ場所へ再送しない。再開時は必要な地形、足場、はしご、収納を再観測する。過去のカーソルや成功ログは現在の安全の証拠にならない。

資材の達成はサーバー由来の持ち物で判断する。鉱石が見つかったこと、掘ったこと、落ちたアイテムが消えたことだけでは必要数量を達成したと数えない。ダイヤ装備は既存の目標に必要な一式の所持・装着確認まで続ける。

必要数が掘削の途中で揃っても、開始した区間の床・照明・封鎖を終えてから帰還する。保存した採掘場は同じワールド・次元・範囲にいる時だけ補給や帰還へ使い、ネザーや遠い探索先の処理へ持ち込まない。

新しく掘る前に、採掘層のラージチェストにある対象資材を実際に確認する。範囲を使い切っても不足する場合は、地上へ戻り、旧坑道と収納の形を保存して保護し、次の範囲を探す。保存は最大8か所・採掘場の履歴は900KB以内とし、候補が未受信なら観測待ちを明示する。無制限に新しい坑道を作り続けない。

## 検証と反映範囲

`branch-mine-*` はプレイヤー用の厳格なテストレーン、入力・設置・半段の支持検証は安全回帰レーンに含める。実際の処理モジュールをつないだテストで、連続移動、位置補正、中断、未知地形、照明の遮蔽、設置の未確認、チェスト54枠と収納量を検査する。

この変更の自動テストは実Realmでの施工完了を証明するものではない。開発時には実Realmへの接続やWindows上で稼働中のBotへの操作を行わない。変更は行動モジュールと入力・採掘処理の範囲で、ホスト・認証設定・依存パッケージは変更しない。取り込み後の動作は既存のホットリロード境界で引き継がれる。
