# プレイヤーモードのブランチマイニング

鉱石への最短経路をその都度掘る方式を、保存した採掘場に通う方式へ切り替える。対象は現世の鉄・石炭・ダイヤ・金・レッドストーン。通常の木材・食料・砂などの調達と、露天掘りモードの範囲・収納方式は別に扱う。

## 採掘範囲と2層

`src/modes/mining/mine-survey.js` が、現在のサーバー接続で受信した World のブロックを読む。画面の鉱石一覧の件数上限や、未受信の地形を空気として扱う推測は使わない。受信中の範囲変更・接続・次元・生存回の変化は計算を中断する。地形の読み取りと候補の評価は区切って実行し、戦闘・停止処理へ実行権を渡す。

`mine-plan.js` は入口の位置、坑道の向き、矩形の大きさ、上下の高さを有限の候補から比較する。矩形の辺は16・24・32ブロックから選ぶ。上層は鉄・石炭、下層はダイヤを中心とする。上層の高さ候補は Y16・32・48。下層は受信した鉱石の高さから選び、特定のYを常に最適とは扱わない。縦坑の深さは191ブロック以内とし、下層の半段の床から地上まで、はしご移動の192ブロック上限内で帰還できる計画に限る。

鉄・石炭を要求された時は、安全を確認できた上層から着工できる。下層の鉱石が未発見・未受信でも、上層の資源まで利用不能にはしない。下層は拡張待ちとして保存し、必要になった時に受信した地形から評価する。拡張時は入口・縦坑位置・向き・上層の坑道と収納・施工履歴を引き継ぎ、新しい下層と延伸する縦坑を確認する。未受信の下層を仮の完成計画として掘らない。従来の2層の保存データも引き継ぐ。

未受信の下層は同じ採掘場を保持して観測する。受信済みの地形から下層の鉱石がない、延伸が危険、深さの上限を超えると確定した場合は、未完作業を片付けて地上へ戻り、上層と収納を履歴へ保存・保護して次の候補を探す。中断・保存失敗・計算予算の上限だけを理由に、既設の採掘場を使い終わった扱いにはしない。

下層の高度候補には、要求中の資源に由来する高さを確保する。ダイヤが見えているために別の高さにある金・レッドストーンの候補を除外せず、必要数量に届く計画と作業量を比較する。

比較するのは、その計画の幹線・支線と制限付きの鉱脈回収で届く鉱石だけ。矩形の中のすべての鉱石を収穫できると数えない。同じ鉱石や同じ施工セルの重複を除き、必要数量を得るまでの掘削、縦坑、床の交換、照明、収納箱、運搬を評価する。結果の最適性は「現在の受信地形と探索予算内の比較」の範囲に限られる。未受信の遠方を含むワールド全体の最適地は分からない。

## 未受信の候補の観測

地形の観測は、対象セルを受信済み、対象区画への要求を送信済み、直近の要求を待機中、対象へ要求できない、の結果を区別する。要求処理が近隣の区画にパケットを送っただけでは、目的の区画へ送信したと扱わない。送信数が0の場合に、未通知の区画なのか通信側の重複抑制なのかを判別できなければ、その不確かさも結果に残す。受信前の要求を採掘計画の根拠にしない。

待つだけで進まない候補は、受信済みの地上で観測位置を変える。立てる床と高さ2ブロックの乾いた空間がつながる同じ高さの経路を探し、通常の移動処理と位置証明で到着を確認する。1回は最大8歩、1候補では最大6回の移動とする。3回の観測を移動判断の基準とし、対象への最初の要求を送れた場合は少なくとも5秒間の受信待ちを取る。未知の床、崖、水、はしご、半段への移動をこの観測処理で新たに計画しない。

最初の9か所の中心は探索開始位置を基準に固定する。使い終えた採掘場がある場合は、近くの候補で計画が成立しなければ96・144・192ブロック離れた8方向も調べる（合わせて33か所。保存した探索は中心を番号で覚えるので、輪は後ろに足すだけにする）。観測でBotが移動しても候補の中心は変えない。安全な経路がない候補や試行を使い切った候補は保留し、残る候補へ進む。再評価は対象セル、観測経路で通れなかった最大64セル、Botが立つマスの変化に基づき、無関係な地形更新だけでは再開しない。同じ接続・生存回の移動回数は再評価後も引き継ぐ。試行数と移動予定は既存のチェックポイントへ保存する。下層の観測で地上へ移る時は、未完の施工と埋戻しを終え、既設の通路とはしごで帰還する。観測できないことだけを理由に既設の上層を退役させない。

候補の中心は拠点から48ブロック以上離れている。サーバーはBotのまわりの区画しか通知しないので、今いる場所から受信できない中心は、8歩の観測移動では受信できないままになる。次の決まりで、そこへ行って調べる（`mine-site-visit.js`）。

- 中心から48ブロックより遠い候補へは観測移動をせず、要求を試したあと保留する。
- 候補を調べ終えて保留だけが残った時は、保留した中心へ1か所ずつ、近い順に長距離移動で行く。着いたら（中心から32ブロック以内）、その候補を観測の回数を新しくして開き直し、そこで受信した地形から計画する。着いたことは地形の証拠にしない。
- 1つの探索（同じ接続・生存回・資源）で、1つの中心へ行くのは1回まで。着けなかった移動も1回に数える。行く予定は、移動を始める前に保存する。全部行っても計画が成立しない時は、従来どおり `MINE_OBSERVATION_EXHAUSTED` で待つ。
- 中心の入口の高さは、中心の列に立てる場所がない時（池・砂浜・未受信）、まわりの列（4・8・12ブロック先の8方向）からも読む。未受信の時に要求するのは、中心の列のセルを先にする。

## 施工

下層を求める場合でも、上層の縦坑と収納室を先に仕上げる。縦坑の着手には、その層までのはしご・照明・施工材を確認する。チェストは踊り場を確認してから収納室の施工前に用意する。

| 部分 | 仕様 |
| --- | --- |
| 縦坑 | 2×2の施工用空間を1段ずつ下りる。固い作業足場から隣の列を掘り、支持壁とはしごを確認してから降下する。非はしご列は踊り場を残して埋め戻す |
| 幹線 | 幅2、高さ3の規則的な通路 |
| 支線 | 幅1、高さ2以上。3ブロック間隔で、支線間に2ブロックを残す |
| 床 | 下付きの丸石ハーフブロック。床ブロックの上端は半段で、その上に2ブロック以上の空間を確保する |
| 鉱脈 | 通路に水平につながる高さ2の小さな空間だけを半径3・最大32掘削ブロックの範囲で追い、追加した穴を埋め戻す。床下や屋根上を任意に掘り抜かない |
| 洞窟 | 通路の横や天井、縦坑の外周への開口を塞ぐ。予定した入口・踊り場を保ち、梯子の横から外部洞窟へ通じる穴を残さない。未受信の空洞へ進まない |

自分を支える床を掘る操作は許可しない。床のハーフブロック化は隣の確認済み足場から行い、置き換えるハーフブロックの所持を先に確認する。下付きの状態・支持範囲・足元の半段の高さを確認した場合だけ、完成した床から通常採掘を続けられる。鉱脈の追加掘削も、その時点で開いた穴をすべて埋め戻せる丸石を確保してから始める。

はしごは専用の `actions/ladder.js` と Runtime の既存入力ストリームを使う。入力の送信や予測位置だけでは到着とせず、実際の位置証明まで待つ。乗降先には支持された足場が必要。戦闘へ操作権が移った場合は、新しい所有者の入力を止めずに自分の処理を中断する。

はしごの結果は採掘側で共通の `status`・`code`・`retry` へ変換する。位置確認待ち、梯子や足場の未確認、操作権の移譲を区別し、既存の「今していること」へ具体的な理由を渡す。ログには計画ID、施工深さ、操作ID、行先、乗降の段階、送信済み入力数、位置確認結果を関連付けて残す。同じ条件での同じ停止は重複記録せず、到着を確認した後は次の停止を新しく記録する。診断のために位置の確認条件を緩めない。

## 湧き潰し

通常の松明と下付きハーフブロックを施工工程に含める。採掘の終了後にバックグラウンド処理へ任せる方式ではない。

受信した通常の松明から、受信済みの開いたマスだけを通る明るさの下限を計算する。目標は8以上。壁・未受信セルを光が透過すると数えず、溶岩、稼働中のかまど、魂の松明をこの証明へ流用しない。これは受信ブロックと既知の発光値からの保守的な計算で、サーバーから照度の数値を直接取得したという意味ではない。

通路の松明は最大6ブロック間隔。広い収納室は両壁に4ブロック間隔で置く。床、頭上の空間、開口の封鎖、照明の確認が揃うまで次の区間へ進まない。すでに存在する敵への対処は従来の戦闘・退避処理を継続する。

## 複数ラージチェストと補給

各層に収納室を設ける。予定する掘削物と鉱石のドロップをスタック数へ換算し、ラージチェスト1個あたり43枠を計画容量とする。54枠のうち11枠を種類の増加やスタックの偏りのために残し、必要な貨物用の個数と補給用1個を配置する。

2つのチェストの設置場所を先に保存し、各設置の受信を確認する。隣接しているだけではラージチェストと判定しない。実際に開いて54枠を受信し、向きと組の対応を確認してから使う。27枠や未受信を成功扱いしない。複数の組は1ブロック以上離し、予定外の組み合わせを防ぐ。

所持品が埋まる前に鉱石・石材を収納する。要求中の資材と修繕用ブロックは手元に残す。満杯なら掘削を止め、石材を捨てる旧処理へ戻さない。取り出し・預け入れは既存の容器受信処理を使い、記憶した内容だけで成功を判定しない。

所持欄の整理では、鉱石の有無だけで完了を判断しない。木材・食料などが枠を占めている時も、作業に必要な携行分を残して余剰を収納し、受信した所持欄に空きができたことを確認する。収納できるものがない状態を、毎回成功として通常作業を遮る結果にはしない。

はしご、床材、松明、チェストは施工前に用意する。最初から下層の依頼が来ても、上層までの未施工分を含めてはしごを準備する。松明の準備で石炭採掘を再帰的に開始しないよう、必要なら木炭を作る。補給は低下した残量に応じてまとめて行う。材料の種類が混ざっている場合のクラフト数は、受信したレシピと所持品のプレビューで実行可能な数へ調整する。

地下で足りなくなった木材などを探し回らず、施工済み通路とはしごで地上へ戻る。作業台・かまどを予定された坑道へ勝手に置かない。ツルハシは実際の採掘と同じ `digTool` で選び、耐久度が不明・残り2以下の道具だけなら補充する。地上の既存設備も開ける視線と立ち位置を確認し、使えないかまどのために所持設備を置けないまま繰り返さない。

補給箱の読み取りも、鉱石を預ける時と同じ入口・梯子・確認済み坑道の経路を使う。長い幹線の端や地上から地下の箱へ一度に通常歩行を要求しない。確認済みの空の補給箱を、同じ不足のまま地上製作の前に毎回確認し直す循環も避ける。

## 保存・再開と達成判定

計画、層ごとの区間カーソル、施工中の操作、鉱脈の埋戻し、収納の登録を、既存のドラゴン遠征のチェックポイントに保存する。大量のブロック配列ではなく線と短い進捗を持ち、既存の1MB制限を維持する。

ワールドに属する計画と、接続・生存回に属する操作の確認を分ける。操作前の予定を保存し、受信した成果を確認してから進捗を保存する。未確認の設置を同じ場所へ再送しない。再開時は必要な地形、足場、はしご、収納を再観測する。過去のカーソルや成功ログは現在の安全の証拠にならない。

縦坑は1段の途中でも再開できるよう、受信済みの下段の梯子・足場と未完の仕上げを照合する。既に取り除いた上段の作業床を再開条件にしない。自分で置いた仮足場の記録は配置の受信証跡と一緒に保存し、保存失敗後に元からあった人工物を自分の足場と取り違えないようにする。

鉱脈の開口が残っている時は、埋め戻し資材を確認し、入口・梯子・該当層を通って作業位置へ戻る。地上から地下へ直接歩こうとして停止したり、資源を切り替えるために未完の開口記録を消したりしない。

上位の進行監視には、保存済みの施工深さと実際に完成した区間数を、過去の採掘場を含む1つの増加する記録として伝える。長い縦坑でも16件の補助イベント上限を使い切らない。新しい計画の選択、未施工区間のスキップ、既設坑道の再確認は施工進捗に数えず、工事が進まない場合の停滞判定は維持する。施工進捗をダイヤなどの所持成果としては扱わない。

資材の達成はサーバー由来の持ち物で判断する。鉱石が見つかったこと、掘ったこと、落ちたアイテムが消えたことだけでは必要数量を達成したと数えない。ダイヤ装備は既存の目標に必要な一式の所持・装着確認まで続ける。

最初の本拠点備蓄では、受信したラージチェスト・所持品・装備から、携行用と予備用の鉄製品の不足を合算する。手持ちの鉄インゴットと原石、本拠点のかまどで確認できた分を使い、残りの鉄の原石を上層の採掘依頼1件で集める。数量を確認して通常の帰路で戻り、本拠点のかまどと作業台で精錬・作成して、携行分を残して予備を収納する。かまどの枠に一度に入らない量は本拠点で続けて処理する。

必要数が掘削の途中で揃っても、開始した区間の床・照明・封鎖を終えてから帰還する。保存した採掘場は同じワールド・次元・範囲にいる時だけ補給や帰還へ使い、ネザーや遠い探索先の処理へ持ち込まない。

新しく掘る前に、採掘層のラージチェストにある対象資材を実際に確認する。範囲を使い切っても不足する場合は、地上へ戻り、旧坑道と収納の形を保存して保護し、次の範囲を探す。保存は最大8か所・採掘場の履歴は900KB以内とし、候補が未受信なら観測待ちを明示する。無制限に新しい坑道を作り続けない。

## 検証と反映範囲

`branch-mine-*` はプレイヤー用の厳格なテストレーン、入力・設置・半段の支持検証は安全回帰レーンに含める。実際の処理モジュールをつないだテストで、連続移動、位置補正、中断、未知地形、照明の遮蔽、設置の未確認、チェスト54枠と収納量を検査する。

補給・再開の回帰には、32ブロックの幹線端からの補給、地上からの未完鉱脈復帰、35枠を使用した所持欄整理、縦坑の各操作直後の中断、配置受信後の保存失敗を含む。上層先行と下層の追加では、実施工済みの上層と収納を保持すること、未受信・危険・保存失敗で既存状態を壊さないことを確認する。進行監視は実際の縦坑施工と仮想時計をつなぎ、54段進んでも保留されず、同じ完成状態を繰り返すだけなら停滞を検出することを確認する。

`branch-mine-bootstrap.test.js` は備蓄の一部が揃った状態で、原木・木の道具・石のツルハシの調達を上位の `home_reserve` 目標へつなぐ。木炭、松明、はしご、床材、採掘場のチェストを作り、上層の施工・鉄の採取・地上帰還・精錬を経て、ツルハシと剣を携行用と拠点備蓄用に1本ずつ得る。2品の原石を一つの採掘目標で集め、本拠点のかまどで精錬することを確認する。縦坑での中断や精錬品の取り出し拒否からも、同じ計画と確認済みの資材を引き継ぐ。

この結合検証は既設の拠点ラージチェストと短い上層計画を用意し、通信相手からのレシピ・所持品・地形・位置の応答を再現する。拠点建設、最初の作業所有者の選択、長距離のチャンク読込、採掘場の選定は同じテストの証明範囲には含めない。候補選定と観測移動は、別の `branch-mine-observation.test.js` で実際の World、要求処理、計画、移動・位置照合をつないで確認する。

この変更の自動テストは実Realmでの施工完了を証明するものではない。開発時には実Realmへの接続やWindows上で稼働中のBotへの操作を行わない。変更は行動モジュールと入力・採掘処理の範囲で、ホスト・認証設定・依存パッケージは変更しない。取り込み後の動作は既存のホットリロード境界で引き継がれる。
