# 管理画面からの接続・ワールド選択・露天掘り

## 起動と操作

Node.js 24以降で、プロジェクトのフォルダーから次を実行します。

```powershell
npm run dashboard
```

同じPCのブラウザーで `http://127.0.0.1:3001` を開きます。`localhost` やLANのIPではなく、このアドレスを使用してください。管理画面を開くだけではBotを起動せず、採掘も開始しません。別途 `npm start` を実行する必要はありません。

1. 「接続と露天掘り」の **Botプロフィール** を確認します。既存の認証を使う場合は `.env` の `BOT_PROFILE` と同じ名前を使います。これはメールアドレスではなく、ローカルの認証保存先を識別する名前です。
2. **ワールド一覧を取得** を押します。必要な場合だけMicrosoft認証コードが画面に出ます。「Microsoftで認証」を開き、Bot用のMinecraftアカウントでコードを入力します。認証が終わると参加済みRealmの一覧を表示します。閉鎖中・期限切れのRealmは選択できません。
3. ワールドを選んで **接続** を押します。参加位置・体力・インベントリの受信が完了するまで、採掘の操作は無効です。`.env` の `REALM_ID` があっても、画面から起動したBotでは一覧から選択したRealmを使います。
4. 開始チャンクX/Zを入力します。1チャンクなら終了X/Zは空欄にします。複数なら両端のチャンクを指定します。**現在のチャンクを入力** は最後にサーバーから受信した位置から計算します。最近の移動がまだサーバー位置に反映されていない場合があるため、表示された範囲を確認してください。
5. **計画を確認** を押します。ワールド名・チャンク・高さ・停止理由・注意事項が表示されます。この時点ではブロックを壊しません。安全条件を満たす計画だけ開始できます。
6. **露天掘りを開始** を押し、確認ダイアログで範囲を再確認します。計画は2分で失効します。入力、接続先、生存回、ジョブ、コード世代が変わった場合は計画を作り直します。

インベントリ、装備、シュルカーボックスの中身、露天掘りの進捗、ライブログは従来の画面で確認できます。操作欄の見出しを押すと折りたためます。

## 範囲と回収方針

| 項目 | 動作 |
| --- | --- |
| ワールド | Minecraft統合版の参加済みRealms。ローカルワールドや任意IPのサーバー接続は追加していません。 |
| チャンク | ブロック座標ではなくチャンク座標。16×16ブロックで1チャンクです。負の座標は切り捨て計算します（ブロックX=-1はチャンクX=-1）。 |
| 最大範囲 | UIからは両端を含む長方形で最大4チャンク。同期的な全域調査の負荷を制限するための上限です。 |
| 次元 | 画面で作る新規ジョブはオーバーワールド限定です。 |
| 上限Y / 下限Y | 空欄なら上限は自動調査、下限はワールド最下層。明示する場合は-64〜319。 |
| 回収・収納 | 既定は「自然取得のみ・満杯で収納」。従来の積極回収・空き容量に応じた収納も選択できます。 |
| 収納先 | 通常は手持ちのシュルカーボックス／チェストを利用します。固定チェストを指定する場合だけチェックを入れてブロックX/Y/Zを入力します。 |

採掘・設置・収納・帰還は既存のBot処理を使用します。保護ブロック、液体、工具の残り耐久、土、脱出経路などの安全条件をUIのために解除していません。計画が通っても、開始後の受信状態によって一時停止することがあります。開始指示の受付は採掘完了の意味ではありません。

## 一時停止・再開・終了

**一時停止** は接続を保ち、保存と現在の処理終了を待ちます。**再開** は現在読み込まれている一時停止中のジョブを、同じワールドで再照合して続けます。**緊急停止** は既存の緊急停止処理へ即時に渡します。どちらも防衛まで無効にする操作ではありません。**ジョブをキャンセル** は現在のジョブを終了し、新しい計画を作れる状態にします。

**切断** は画面が起動した子Botに停止を要求し、終了を確認します。通常停止が完了しない場合は、12秒後からプロセスの終了を段階的に試みます。強制終了時は未確定のチェックポイントが残る可能性があるため、復旧時に確認してください。応答がタイムアウトした場合は「失敗したから未実行」と決めつけず、現在の状態を再確認します。書き込み操作は自動再送しません。

ブラウザーのタブを閉じてもBotは止まりません。管理画面サーバーをCtrl+C等で終了すると、その管理画面が起動した子Botも停止します。異常終了でもIPC切断を検知した子Botは停止します。別ターミナルで起動したBotは、管理画面を終了しただけでは停止しません。

画面経由の接続では、過去のジョブの自動復旧を無効にしています。ワールド選択・接続だけで過去の採掘を勝手に再開しません。保存済みジョブを明示的に読み込む既存API/CLIは残していますが、ファイル選択UIはこの変更の範囲に含めていません。

## 既にBotが起動している場合

同じAPIポートに既存プロセスがある場合は新しいBotを起動しません。対応する操作APIを持つ更新済みのBotなら、そのまま計画・開始・停止・明示的な切断ができます。旧版のBotは操作APIを持たないため、現在の作業を安全に停止してから更新・再起動してください。

ワールドやプロフィールを変更するときは、先に切断し、もう一度一覧を取得します。普段のゲーム画面と同じアカウントを使う場合は、ゲーム側を対象Realmから退出させてください。

## 更新とセキュリティ

この機能はレビュー安全対策PR #8のコードを前提としています。**Bot本体と管理画面の両方を再起動**してください。`host.js`、`api.js`、管理画面サーバーの変更は、行動コードのホットリロードだけでは反映されません。既存の未コミット変更、`.local/quarry`、認証キャッシュを保全して更新します。

操作経路はローカルPC限定です。Host・Origin・JSON形式・要求サイズ・一時トークンを検査します。ブラウザーに汎用 `/action` プロキシや任意コマンド実行機能を渡していません。子プロセスは固定エントリーポイントで起動し、シェルにユーザー入力を渡しません。

Microsoft認証は公式ページで行います。パスワードやアクセストークンを管理画面へ返しません。デバイスコードだけを認証中に一時表示し、認証完了・期限切れ・切断後は表示しません。このコードは機密扱いにし、第三者へ渡さないでください。表示用JSONキャッシュには保存しません。`.env` は読み込みのみで、UIから書き換えません。

これは同じPCを利用する信頼できる利用者向けであり、複数利用者の権限管理やインターネット公開用の認証ではありません。ポートを外部公開したり、トークン検査を無効化したりしないでください。

## 検証

```powershell
npm run check
npm run test:review
```

`test/dashboard-control*.test.js` が入力境界・接続世代・計画失効・重複実行・停止中の排他・IPC・プロセス所有権・Origin/トークンを検証します。既存のダッシュボード・採掘・戦闘・収納・ホットリロードの関連テストも併せて実行します。

画面の操作検証では、実HTML/CSS/JavaScriptをブラウザーで動かし、通信とRealmデータを模擬しています。HTTP境界はローカルの実HTTPサーバーでも検証します。**実際のMicrosoftログイン・実Realmへの接続／採掘、利用者PCへのインストールは未実施**です。
