# 管理画面からの接続・ワールド選択・露天掘り

## 起動と操作

Node.js 24以降で、プロジェクトのフォルダーから次を実行します。

```powershell
npm run dashboard
```

同じPCのブラウザーで `http://127.0.0.1:3001` を開きます。`localhost` やLANのIPではなく、このアドレスを使用してください。管理画面を開くだけではBotを起動せず、採掘も開始しません。別途 `npm start` を実行する必要はありません。

1. 「接続と露天掘り」の **Botプロフィール** を確認します。既存の認証を使う場合は `.env` の `BOT_PROFILE` と同じ名前を使います。これはメールアドレスではなく、ローカルの認証保存先を識別する名前です。
2. **ワールド一覧を取得** を押します。必要な場合だけMicrosoft認証コードが画面に出ます。「Microsoftで認証」を開き、Bot用のMinecraftアカウントでコードを入力します。認証が終わると参加済みRealmの一覧を表示します。閉鎖中・期限切れのRealmは選択できません。
3. ワールドを選んで **接続** を押します。参加位置・体力・インベントリの受信が完了するまで、採掘の操作は無効です。`.env` の `REALM_ID` があっても、画面から起動したBotでは一覧から選択したRealmを使います。
4. 開始X/Zにブロック座標（ゲーム内の座標）を入力します。その座標を含むチャンク全体が範囲になり、入力を終えると範囲の端の座標に揃えて表示します。1チャンクなら終了X/Zは空欄にします。複数なら両端の座標を指定します。マス目と露天掘り欄の範囲もブロック座標で表示します。Botへ送る範囲は従来どおりチャンク単位です。**現在地** は、Botがいるチャンクを入力します。サーバーから確認した位置があればそれを使い、なければBotが報告している位置を使います（範囲の選択だけで、ワールドは変更しません）。コントロール欄は常に開いたままで、見出しを押しても閉じません。
5. **Botを移動させる** を押すと、選択範囲内の乾いた足場へ通常歩行で移動します。半径48m以内の既知地形で、迂回を含む128mまでの歩行を計画し、短い区間ごとに実位置を確認します。経路の計算中も中断と防衛を維持します。経路がない、未受信の地形がある、被弾した場合などは停止します。体力が低いだけでは移動を拒否しません（2026-11-13 ユーザー方針）。死亡時と体力が未受信のときだけ拒否します。移動中と失敗は、体力の下の「今していること」欄に理由つきで表示します。失敗と中断の理由（コード・現在位置・目標・歩行の停止理由）はBotのログに `チャンク移動に失敗:` として1行残ります。移動中の **中断** で止められます。範囲の選択だけでは移動しません。
6. **デバッグチェスト設置** は、確認済みのBot位置が選択範囲に収まる場合だけ有効になります。押せない間は、ボタンの右上に理由（未接続・移動中・収納中・採掘中・範囲を選択・範囲の外・位置が未確認）を表示します。Botが範囲内にいて位置だけ未確認のときは、移動ボタンが **位置を確認** に変わります。押すと同じ移動操作がサーバーへ位置を照会し、体全体が範囲内にあれば足場にかかわらず歩かずに確認だけを取ります。**現在地** を押したときも、位置が未確認ならそのままこの確認まで進みます。設置確認後に範囲や位置が変わった場合は確認を作り直します。到着だけではチェストを設置しません。
7. **計画を確認** を押します。ワールド名・チャンク・高さ・停止理由・注意事項が表示されます。この時点ではブロックを壊しません。安全条件を満たす計画だけ開始できます。
8. **露天掘りを開始** を押し、確認ダイアログで範囲を再確認します。計画は2分で失効します。入力、接続先、生存回、ジョブ、コード世代が変わった場合は計画を作り直します。

インベントリ、装備、シュルカーボックスの中身、露天掘りの進捗、ライブログは従来の画面で確認できます。操作欄の見出しを押すと折りたためます。

## 範囲と回収方針

| 項目 | 動作 |
| --- | --- |
| ワールド | Minecraft統合版の参加済みRealms。ローカルワールドや任意IPのサーバー接続は追加していません。 |
| チャンク | ブロック座標ではなくチャンク座標。16×16ブロックで1チャンクです。負の座標は切り捨て計算します（ブロックX=-1はチャンクX=-1）。 |
| 最大範囲 | UIからは両端を含む長方形で最大4チャンク。同期的な全域調査の負荷を制限するための上限です。 |
| 次元 | 画面で作る新規ジョブはオーバーワールド限定です。 |
| 上限Y / 下限Y | 空欄なら上限は自動調査、下限はワールド最下層。明示する場合は-64〜319。 |
| 回収・収納 | 既定は「自然取得のみ・満杯で収納」。従来の積極回収・空き容量に応じた収納も選択できます。 |
| 収納先 | 手持ちの収納用シュルカーボックスだけを利用します。固定チェスト登録は廃止しました。補給用4箱は収納候補から除外します。 |

採掘・設置・収納・帰還は既存のBot処理を使用します。保護ブロック、液体、工具の残り耐久、土、脱出経路などの安全条件をUIのために解除していません。計画が通っても、開始後の受信状態によって一時停止することがあります。開始指示の受付は採掘完了の意味ではありません。

## 一時停止・再開・終了

**一時停止** は接続を保ち、保存と現在の処理終了を待ちます。**再開** は現在読み込まれている一時停止中のジョブを、同じワールドで再照合して続けます。画面の緊急停止ボタンは一時停止と同じ止め方だったため、一時停止に統合しました（2026-11-13 ユーザー方針）。一時停止は他の操作の処理中でも押せ、移動・収納・デバッグチェスト設置の中断にも使えます。防衛まで無効にする操作ではありません。**ジョブをキャンセル** は現在のジョブを終了し、新しい計画を作れる状態にします。

**切断** は画面が起動した子Botに停止を要求し、終了を確認します。通常停止が完了しない場合は、12秒後からプロセスの終了を段階的に試みます。強制終了時は未確定のチェックポイントが残る可能性があるため、復旧時に確認してください。応答がタイムアウトした場合は「失敗したから未実行」と決めつけず、現在の状態を再確認します。書き込み操作は自動再送しません。

ブラウザーのタブを閉じてもBotは止まりません。管理画面サーバーをCtrl+C等で終了すると、その管理画面が起動した子Botも停止します。異常終了でもIPC切断を検知した子Botは停止します。別ターミナルで起動したBotは、管理画面を終了しただけでは停止しません。

画面経由の接続では、過去のジョブの自動復旧を無効にしています。ワールド選択・接続だけで過去の採掘を勝手に再開しません。保存済みジョブを明示的に読み込む既存API/CLIは残していますが、ファイル選択UIはこの変更の範囲に含めていません。

## 既にBotが起動している場合

同じAPIポートに既存プロセスがある場合は新しいBotを起動しません。対応する操作APIを持つ更新済みのBotなら、そのまま計画・開始・停止・明示的な切断ができます。旧版のBotは操作APIを持たないため、現在の作業を安全に停止してから更新・再起動してください。

ワールドやプロフィールを変更するときは、先に切断し、もう一度一覧を取得します。普段のゲーム画面と同じアカウントを使う場合は、ゲーム側を対象Realmから退出させてください。

## 更新とセキュリティ

この機能はレビュー安全対策PR #8のコードを前提としています。**Bot本体と管理画面の両方を再起動**してください。`host.js`、`api.js`、管理画面サーバーの変更は、行動コードのホットリロードだけでは反映されません。既存の未コミット変更、`.local/quarry`、認証キャッシュを保全して更新します。

操作経路はローカルPC限定です。Host・Origin・JSON形式・要求サイズ・一時トークンを検査します。ブラウザーに汎用 `/action` プロキシや任意コマンド実行機能を渡していません。子プロセスは固定エントリーポイントで起動し、シェルにユーザー入力を渡しません。

Microsoft認証は公式ページで行います。パスワードやアクセストークンを管理画面へ返しません。デバイスコードだけを認証中に一時表示し、認証完了・期限切れ・切断後は表示しません。このコードは機密扱いにし、第三者へ渡さないでください。表示用JSONキャッシュには保存しません。`.env` は読み込みのみで、UIから書き換えません。

これは同じPCを利用する信頼できる利用者向けであり、複数利用者の権限管理やインターネット公開用の認証ではありません。ポートを外部公開したり、トークン検査を無効化したりしないでください。

## 検証

```powershell
npm run check
npm run test:review
```

`test/dashboard-control*.test.js` が入力境界・接続世代・計画失効・重複実行・停止中の排他・IPC・プロセス所有権・Origin/トークンを検証します。既存のダッシュボード・採掘・戦闘・収納・ホットリロードの関連テストも併せて実行します。

画面の操作検証では、実HTML/CSS/JavaScriptをブラウザーで動かし、通信とRealmデータを模擬しています。HTTP境界はローカルの実HTTPサーバーでも検証します。実Realmでのチャンク移動と設置可否は下記の2026-11-12記録を参照してください。露天掘り全体の完了検証は継続中です。

## 初期アイテム

採掘エリアの **デバッグチェスト設置** は確認ポップアップ付きの明示的なリセットです。現在の所持品・防具・所持箱の中身を置き換えます。安全条件、標準セット、必要な権限と失敗時の対処は [loadout-reset.md](loadout-reset.md) を参照してください。


## チャンク移動と位置確認の更新

固定操作 `moveToChunk` / `cancelChunkMove` を追加しました。通常移動だけを使用し、テレポート・掘削・足場生成は行いません。探索半径48mと累積歩行128mを分け、最大32区間・180秒で制限します。長い経路は小分けに計算し、各区間の実行前に通常の移動判定をやり直します。移動中は計画・開始・補給初期化・手動収納を受け付けず、戦闘へは即座に操作権を渡します。中断後に古い移動の後処理が新しい戦闘移動を停止しないよう、操作IDと移動世代を照合します。

画面の位置表示と設置可否は受信した位置、または同じ接続・次元・生存回の読み取り専用 `/testfor @s[...]` 応答を使用します。予測位置や入力送信だけでは到着扱いにしません。ページ表示・状態取得から位置照会や移動を実行しません。確認後の範囲・接続・コード世代変更は設置確認を失効させます。

この更新の固定操作受付は接続側で読み込まれるため、**Bot本体と管理画面の再起動が必要**です。旧受付のまま新しい画面を開いた場合、移動・デバッグ設置ボタンは無効になります。


2026-11-12の最終検証では `npm run test:review` は1,345件すべて成功し、`npm run check` は661ファイル＋ダッシュボード1スクリプトが成功しました。画面・固定操作・通常歩行・実位置証拠・範囲に結び付いた初期化の回帰を含みます。

全件比較の生ログは、直前の `2aed2cd` が5,057件（成功4,783・失敗261・キャンセル12・スキップ1）、変更中の実行が5,165件（成功4,883・失敗268・キャンセル13・スキップ1）、追加失敗9件・消失1件でした。追加のうち8件は、実行開始後に整合した既存テストの範囲指定・抽出処理の依存設定です。修正後に管理操作6件・引継ぎ5件・水中待機6件が成功し、最終の関連1,345件も成功しています。残り1件は、変更していない通常チェスト増設シミュレーションの30秒タイムアウトです。同じ30秒制限の単独再実行では約28.8秒で成功し、基準の約28.9秒と同程度でした。最終テスト設定で全件比較を再実行した結果ではなく、全件成功・PR全体の回帰差分解消とは扱いません。


実Realmでは、管理画面の「Botを移動させる」からチャンク (126, 124) へ通常移動し、足元約 (2022.5, 76, 1997.56) を同じ接続・生存回の `server_position_volume` 応答（半径0.2m）で確認しました。「到着確認済み」と設置ボタンの有効化、別の (127, 124) を選択した場合の無効化、元の範囲へ戻した場合の有効化もブラウザーで確認しています。設置と採掘は実行していません。

長い経路は実行用の短区間へ切り出し、その都度現在の位置から通常移動を再プレビューします。水を含む経路の乾いた出発地点でも小さな歩行入力を選択し、受信済みの位置補正は同じ目標・元のtick/時間制限・最大3回の条件で再計画します。チャンク移動の脅威判定は既存の戦闘側の射線・敵からの到達判定を使い、クリーパーと未確認の情報は従来どおり拒否します。他の通常水辺移動の方針は変更していません。

到着後の待機物理による3cm以内の微小な変化は、実受信した中心・時刻を変えず、その変化量を確認半径へ足して扱います。待機以外の移動、接続・コード世代の変更、範囲超過で位置証拠を失効させます。

戦闘へ移行した場合、位置補正後の支持された着地を確認できない場合、実位置の照合が通らない場合は安全側で中断します。自動再送や例外の自動承認はせず、着地と作業終了を確認してから同じボタンで再実行します。
