# 移動・退避・帰還収納の復旧

移動の探索、採用、実行で判定が異なることと、下位の失敗理由を上位が捨てることによる停止・反復を修正する。経路のプレビューや操作の送信を、ゲーム内の成功とは扱わない。

## 移動

- 陸上の通過点の身体の空きは、Navigator と同じ衝突判定で再確認する。収納場所の植物名リストで、衝突しない植物の経路を捨てない。目的地の空気条件・整数の足元高さ・既存の床と水の条件は維持し、全媒体の移動範囲を広げる変更にはしない。未受信・保護された場所などの確認も残す。
- 非同期探索は、実際に読んだサブチャンクを追跡する。無関係な場所の更新や地形を変えない受信では中止しない。参照した地形の更新、消失、接続側の世代変更は検出する。
- 参照地形が探索中に変わった場合の再計画は有限回。操作権の一時占有、計画の失効、経路なしを区別し、上位へ元の原因を保持する。
- 敵の回避条件を長区間の探索、短区間のプレビュー、移動開始へ渡す。実行時も現在の敵を再検査する。
- 長距離移動の代替候補は、1周の上限を維持して、次の周では未試行の方向へ進む。受信した位置のセル・接続・生存回などが変われば失敗履歴を更新する。全候補が一巡した後は再評価できる。操作権や計画失効による中断は、その方向の経路失敗として記憶しない。
- 探索が返した理由、最後に試した候補、未受信地形、経路の採用を拒否した点を診断に保持する。

## 戦闘への退避の引き継ぎ

戦闘への即時の操作権移譲を維持する。戦闘の後退も、既存の水面・岸への移動を利用し、陸上に限った候補で終わらないようにする。

水を許可するだけではなく、受信した身体・水面・頭上の地形、予測した全行程、敵から離れる方向を確認する。実行中も同じ条件を確認する。水面を移動できることから、未受信の水底や陸地の存在を推定しない。

待機保護の終了は、戦闘への引き継ぎ、別の操作への引き継ぎ、接続・プレイヤーの変更、実行世代の変更を型付きの理由で区別する。引き継ぎや取消しを、経路失敗や退避成功として数えない。

## 帰還収納

- 収納拒否の詳細を保持し、箱が開かない・満杯・持ち物側の不一致・結果未確認を区別する。収納要求の拒否だけで、正常に開いたチェストを利用不能にしない。
- 確認済みの持ち物側の拒否は、既存の再同期処理につなぐ。今回の要求に対応する新しい受信を確認してから再試行する。要求を送っただけで同期完了や収納成功にはしない。
- 同じ拒否を繰り返す場合は、既存の有限の試行予算で保留する。拒否原因を木材不足へ置き換えない。
- 満杯という観測は、保留解除・復元時などに読み直す。一度満杯だった箱を永久に除外しない。
- 隣接しているだけで同じ容器とみなさない。受信した54枠と一意な隣接候補など、確認できる組だけで状態を共有する。確認できない隣接箱は別々に検査する。

帰還の詳細な段階・再同期の条件は [player-return.md](player-return.md) を参照。

## 検証と反映

実モジュールを接続したオフライン回帰で、衝突しない植物、探索中の地形更新、敵の迂回、後続の代替候補、水を通る退避、収納拒否と再受信、満杯情報、独立した隣接チェストを確認する。

構文確認と厳格な安全・プレイヤーレーンは `npm run check`、`npm run test:review`、`npm run test:player`。既存全件の失敗差分と Windows の回帰は PR の CI でも確認する。既存失敗が残る全件比較を、全テスト成功とは表現しない。

`src/host/world.js` と接続側の地形観測器を変更するため、**取り込んだ後は Bot 本体の再起動が必要**。稼働中の Bot に対する起動・停止・再接続を、この修正作業では実施しない。

実Realmでの歩行・退避・収納の成功、添付ログの各発生時の地形・受信パケットとの一致は未検証。オフラインの経路案・模擬応答・テスト合格を、実Realmでの達成の証拠にはしない。
