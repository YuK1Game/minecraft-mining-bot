# 所持品・経路探索・食料確保のレビュー対応

レビューで再現した、所持品の古い応答による上書き、資材を使う経路の取りこぼし、中断後の移動開始、道具を取得しても残る失敗記録、炉内の残り物を無視した調達、同じ食料探索先の反復に対処する。

## 所持品の更新

装備と破棄は、要求に対応するサーバー応答の対象スロット、個数、stack ID と現在の受信状態を照合する。確認できた枠だけを差分として更新し、未受信の枠を空として補完しない。

要求後に別の持ち物を受信した場合、古い応答から要求時のアイテムを復元しない。装備の入替えでは移動先だけでなく持ち物側の結果も確認する。対象枠の応答が欠けていることや、要求を送信したことは、成功の証拠にしない。

## 移動と探索

- 建築を伴う経路は、同じ座標への到達でも資材の使用量が異なる状態を保持する。短い区間でブロックを使い切る経路によって、資材を温存する迂回路を捨てない。
- 長距離移動は、非同期の通過点探索や道具選択が完了した直後にも中断を確認する。中断後に新しい採掘・移動を始めず、中断を経路失敗として記憶しない。
- 建築歩行の失敗記録は、同じ条件での無限反復を防ぎつつ、道具・対象地形・実行スコープが変わった場合に見直す。無関係なチャンクの更新だけで全部の失敗記録を捨てない。
- 広域経路の診断も非同期で処理する。既定の探索時間は1秒、指定可能な上限は2秒。通常の探索スライスの目安は8msで、ノード間の確認地点で制御を戻す。落差の入力にも上限を設け、1つの列だけで探索を占有しない。時間切れは `timedOut` として返し、途中の経路を目的地到着とみなさない。中断・Runtime破棄・参照した地形の更新で古いプレビューを破棄し、無関係なチャンクの受信では探索を続ける。実際の移動を行う広域探索の時間予算は別に維持する。

## 食料確保

かまどは受信した内容を確認してから、完成品の回収、残った原料と燃料の利用、不足分の投入へ進む。手元に生肉や石炭がないだけで、炉内の完成品や燃料を無視しない。上位の食料調達も近くの既設炉や調理途中の炉を先に確認する。

小麦が十分あり、パンを作れる場合は、その選択を生肉の調理と分ける。生肉も持っているために不要な石炭探しへ進まない。

食料探索の巡回数と畑へ戻る周期を分ける。定期的に畑へ戻りながら、探索方向を一巡し、外側の範囲へ進める。

## 回帰テストと残る確認

実際の所持品Storeと装備・破棄処理、経路計画と実行側の入口、食料判断と炉の処理、Runtimeの診断入口をつなぐオフライン検証を行う。模擬応答や合成地形を使う箇所は、実Realmの受信記録と同一とは扱わない。

落ちた資材への通路を開く既存テストは、保存済みの階段地形で不具合を再現した。歩行可能セルの数値キーと、通路探索側の文字列キーが不一致だったため、共通の `cellKey` に統一した。保護された石・未受信・人工物・鉱石を掘らない回帰も加え、`player-drop-access.test.js` を厳格なプレイヤーレーンへ戻す。

必須の検証は `npm run check`、`npm run test:review`、`npm run test:player` と、CIのWindows回帰・3分割の全件比較。全件比較の合格は、基準から新しい失敗が増えていないことを意味する。残っている既存失敗を全テスト成功と表現しない。

接続側の `src/host/`、認証、依存関係、環境設定は変更しないため、この修正自体のためのBot本体の再起動は不要。稼働環境でコードを取り込み、通常の安全な切替点でホットリロードする。GitHubでのマージと、利用者のPCへの反映は別の操作であり、マージだけで稼働中のBotに反映されたとはみなさない。

実Realmでの装備・破棄・歩行・採掘・調理・食料回収は未実施。オフラインの計画成功やテスト合格から、ゲーム内で達成済みとは判断しない。
