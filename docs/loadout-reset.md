# シュルカー専用収納と初期セットリセット

## 操作

Botを接続し、採掘・収納・回収を安全に停止してから、所持品パネルの **初期セット** を押します。ワールド・Bot名・セット内容・一時箱の座標を確認し、確認ダイアログの **リセットする** を押してください。閉じる／戻る／Escapeでは実行しません。

CLI（Windows cmdを含む）:

```text
npm run loadout:reset -- --preview
npm run loadout:reset
```

実行時は表示内容を確認し、対話入力で `RESET` と入力します。CLIは既に接続しているローカルBotを使用し、別Botを起動しません。非対話の強制実行、任意コマンド、任意プレイヤー名や任意の配布内容を受け取るインターフェースはありません。

**現在のメイン所持品・装着防具・オフハンド・持っているシュルカーの中身を置き換えます。元には戻せません。** エンダーチェスト、既設の箱、他プレイヤーの所持品は消しません。画面を開くだけ、プレビュー取得、接続、起動ではリセットしません。

リセット後は採掘計画を作り直してください。旧ジョブは保存を確認してキャンセルされ、採掘は自動再開しません。

## シュルカー専用

本番Runtimeの露天掘りはシュルカーだけを使います。固定チェストの設定UIと `chest=` 指定を廃止し、持ち運びチェスト／ダブルチェストへの代替・チェスト増設は無効です。旧版互換の内部部品は読み取り・復旧テスト用として残していますが、UI・CLIから本番のチェスト収納へ切り替えることはできません。

青・空色・黄・茶は補給専用色で、未登録・使い切り後でも採掘物の収納候補から除外します。他の色の補給箱を明示登録した場合も、その受信スタック識別子を除外します。4種類の中身を初期計画で識別できた場合は補給箱として登録します。収納用シュルカーがない計画は `NO_CARGO_SHULKER` で開始不可です。

既存の固定チェストジョブは保存内容や未回収容器の記録を消さず `LEGACY_CHEST_STORAGE` で停止します。既設・未回収の容器を確認してからキャンセルし、シュルカーの新規計画を作ってください。未確定収納をリセットで帳消しにすることはできません。

## リセットの条件と実装

オーバーワールド・生存・サーバー権威のインベントリを必要とします。リセット前の防具・オフハンド等が未受信でも確認画面は開けます。明示確認と権限確認の後、未受信の枠に一時アイテムを設定して実際のスロット更新を受信し、それから消去・初期セットの配布へ進みます。受信なしの送信成功を完了とは扱いません。乾いた安全な足場、周囲の受信済み空間が必要です。デバッグ専用のため、他プレイヤー・敵対モブ・位置不明のエンティティがいても実行できます。炎上・生存中の被弾だけでは停止しません。実行確定後に既存の戦闘入力を停止して終了を待ち、初期化へ操作権を渡します。収納・回収・帰還・保存失敗が未解決、または他の操作が動作中の場合も拒否します。

**コマンドが許可されたサンドボックスとBot自身のオペレーター権限が必要**です。最初に読み取り専用 `/testfor @s` で権限を確認します。拒否時には所持品を消しません。これは管理者による初期化機能であり、通常採掘へのアイテム生成の混入ではありません。

通常のBedrockコマンドでは任意NBTを `/give` のJSONで注入できないため、次の方式を取っています。

1. 対象は常にコマンド実行者自身の `@s`。受信した状態と同じ接続・次元・生存回に限定します。
2. 自分の周囲2ブロック先の既知の空気1マスを選び、`setblock … keep` で一時的な補給用シュルカーを作ります。既存ブロックを上書きしません。
3. 工具を自身のホットバーに生成・エンチャントし、通常の受信確認付き格納で27本入れます。パンと土も全27枠を確認します。
4. `loot replace entity @s … mine` で完成した箱を指定枠に入れ、受信した箱のNBTから27枠の種類・数量・エンチャントを照合します。
5. 一時箱の中身をもう一度照合し、全27枠を空にしてから、同じ箱である条件を付けて撤去します。未確認・変更された箱は勝手に消しません。
6. 全所持品・防具・箱内容・空き枠・一時箱撤去と保存を確認して初めて完了を表示します。

確認トークンは120秒、一度きり。確認後の接続・生存回・位置・所持品・ジョブ・コード世代の変更は失効します。生存中の体力変化は失効条件ではありません。リセット中は他の作業／自動再開／ホットリロードと排他し、明示中断・死亡・場所変更・応答消失で止まります。被弾に伴う防具破損やノックバック等で内容・座標の実測が変われば、該当工程の照合で停止する場合があります。操作送信だけを成功扱いせず、破壊的な要求を自動再送しません。

## 失敗・中断

複数のコマンドをまとめて取り消すサーバートランザクションではありません。途中で止まると、持ち物が部分的に置き換わることがあります。完了とは表示しません。原因と一時箱の座標は画面、途中記録は `.local/loadout-reset/` のワールド別JSONで確認できます。認証トークンやパスワードは保存しません。

未確認の一時箱が残っているときは、箱と中身を実際に確認・回収してから、再度プレビューしてください。再実行は新しい確認が必要で、現在残っている持ち物も再び置き換えます。コマンドの権限やサーバー仕様の不一致を理由に、安全確認を解除しないでください。

## 更新・検証

`host.js`・Runtimeの配線・ダッシュボードAPIを変更したため、**Bot本体と管理画面サーバーを両方再起動**します。未コミット変更と実ジョブJSONを保全してください。

```text
npm run check
npm run test:loadout
npm run test:review
```

テストは模擬サーバー応答、実際のNBT読み取り、確認トークン、HTTP境界、停止・失敗を検証します。実Microsoftログイン・実Realmでのリセット／採掘の成功とは区別します。実Realmの受入時は安全な場所で、既存の持ち物を別に退避し、Botに権限があることを確認して手動実行してください。

## 2026-11-09 受信待ちの修正

初期状態の全装備受信をリセットの入口条件から外しました。未受信枠の同期は確認後のみ実行し、所持品・防具・オフハンドが実受信で確定するまで制限時間付きで照合します。タイムアウト時は不足している区分を表示します。同期用に設定した一時アイテムは途中失敗時に残る場合があります。受信していない枠を空扱いする処理や自動再送は追加していません。

防具4枠／所持品36枠が個別の `inventory_slot` で届く場合も、同じ生存回の全枠受信で確定します。1枠だけ・過去の生存回・件数だけの応答では確定しません。接続中の持ち物はこのコード修正時には操作していません。

## 2026-11-09 エンチャント前の手持ち確認

リセットでは毎回 `mob_equipment` を送り、ローカルの選択枠が同じでも省略しません。続いて本人限定の `/testfor @s[hasitem={item=...,location=slot.weapon.mainhand,quantity=1}]` でサーバー側の手持ちを確認してから `/enchant` へ進みます。補給工具・防具・最終ホットバーに共通の処理です。送信だけでは持ち替え成功としません。

読み取り専用の手持ち照会に「対象なし」が返った場合だけ、選択と照会を最大3回行います。タイムアウト・権限拒否・エンチャント等の変更コマンドは自動再送しません。通常の戦闘・採掘の持ち替えは変更していません。

以前の失敗で一時シュルカーが残っている場合、表示された座標の箱と中身を確認して回収してから再実行します。残置箱を勝手に削除したり、途中の所持品を復元済みとして扱う処理はありません。実Realmでの検証は別途必要です。

## 2026-11-09 収納用シュルカーを8個に変更（標準v2）

拾わない設定（passive）・満杯時収納の露天掘りでは、空の紫シュルカー20個と補給4箱が25枠を占め、作業用の空きが1〜2枠しか残りませんでした。収納のたびに、箱を拾い直すための空き枠が足りないと判定されて停止していました（STORAGE_PICKUP_CAPACITY_REQUIRED）。標準セットの空箱を8個（メイン所持品9〜16）に減らし、17〜28を空き枠にしました。バージョンは `quarry-standard-v2` です。シュルカーはシュルカーの中に入れられないため、余った空箱をジョブ内の収納へ移す方法はありません。
