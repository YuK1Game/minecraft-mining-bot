# 2026-11-09：採掘上限と地上着地点の高さを分離

## 再現した問題

利用者のログは、岩盤入口修正後の `RECONCILE → PAUSED(EXIT_COLUMN_UNAVAILABLE)`、候補の理由は `LANDING_UNAVAILABLE` でした。

旧プランナーは、着地点の床を採掘上限 `yTop` の16ブロック下までしか探していませんでした。採掘上限が85、隣接する地表が63の模擬地形では、確認済みの安全な地表があっても全64候補が拒否されました。木や山で採掘範囲の上限が高くなる場合に、隣接地表の高さを同じと仮定できません。

これは同じエラーに至るコード経路の再現です。利用者PCの完全な地形・停止詳細は未取得のため、実環境の全候補がこの原因だったとは断定しません。

## 修正

- 読み取りはワールド上端から帰還入口の高さまで。根拠のない `yTop - 16` という探索下限を撤廃します。採掘範囲の上限・下限は変更しません。
- 空気の連続した実受信を必要とし、最初の障害物で探索を止めます。未受信の空間・屋根・葉・水や溶岩を飛び越えて洞窟の床を地上扱いしません。
- ワールドの高さ、着地点の上限、床と頭上、明示的保護、選択した1列のみの権限、土の必要数・工具耐久・収納容量・最終到達経路の照合を維持します。通常採掘・戦闘・収納・初期セット・通信は変更しません。
- `pauseDetails` は原因 `cause` と代表座標 `position` を候補一覧より先に返します。既存の短縮ログでも、`UNKNOWN`、`FLUID_OR_EXTRA_LAYER`、`UNSAFE_LANDING_FLOOR`、`LANDING_TOO_HIGH` 等を確認できます。未受信時は詳細に元の観測理由も保持します。
- 地形の再取得は従来の同一接続・生存回で最大2回のまま。再開ボタンの連打で上限をリセットしません。受信済みの低い地表なら再取得せず再評価できます。
