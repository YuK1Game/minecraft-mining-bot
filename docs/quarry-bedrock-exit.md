# 2026-11-09：ワールド下限指定時の帰還入口

## 不具合

採掘範囲の下限 `yBottom` を帰還時の足位置にも使っていたため、`yBottom=-64` では入口に岩盤がある、または足場にワールド外のY=-65を要求することで、全候補が `ENTRY_UNAVAILABLE` となり `PREFLIGHT` で停止していました。

利用者のログは `Y 85 → -64 / EXIT_COLUMN_UNAVAILABLE`。利用者の実地形データは未取得です。同じ高さ条件を持つ模擬地形で旧実装の拒否を再現しました。

## 修正

- 採掘下限と帰還の足位置を分離。各候補の内側の入口列を観測し、範囲内に岩盤があれば、その最上段の1ブロック上を入口にします。岩盤がない通常の深さ指定は従来の下限位置を使います。
- 岩盤面の高さは実データから選びます。Y=-59等への固定や、採掘範囲の下限の書き換えは行いません。
- 帰還列の床・入口2マス・頭上・地上着地点・土・道具を照合します。掘削しない横壁の岩盤は許可しますが、帰還列内の岩盤や明示的な保護、水・溶岩・落下物は従来どおり拒否します。
- ワールド外の座標を地形未受信として再取得しません。未受信の有効座標は安全扱いにせず、既存の地形取得処理で再評価します。
- 事前計画は予測であり実行許可ではありません。最終帰還では実際の空気・床・入口までの到達経路を再確認します。採用した1列以外への掘削権限は増えません。
- 候補が使えない場合の詳細に、問題の箇所・座標・原因を追加しました。

## 更新

`git pull --ff-only origin main` 後、行動コード反映のログを確認し、管理画面の「再開」を押してください。現在の `EXIT_COLUMN_UNAVAILABLE` の一時停止ジョブは再評価できます。初期セットのリセットや採掘下限の変更は不要です。接続ホスト・管理画面サーバー・依存パッケージの変更はありません。
